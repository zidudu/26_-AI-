**자동차 동호회 모니터링 · Version 1.0 — 정식 배포판**

사용자에게 표시하는 정식 명칭은 **자동차 동호회 모니터링 · Version 1.0**입니다. 개발 이력 추적을 위한 내부 버전은 **10.0.0**으로 유지합니다. RC1.7의 기능을 유지하고, 제목·버전 표기·배포 안내를 정리했습니다.

처음 사용하는 분은 같은 폴더의 **`00_실행순서.png`**를 따라 진행하세요. 기존 `naver_cafe_v5` 폴더는 필요하지 않습니다. ZIP에 포함된 `engine` 폴더의 엔진과 기본 설정으로 시작하며, DB는 첫 실행 때 자동 생성됩니다.

**받는 사람의 준비 사항**

- Windows, Python 3.11 이상(`py` 실행기 포함), 설치된 Chrome.
- Codex 방식 AI 분석: Codex CLI 설치 및 본인 ChatGPT 계정 로그인. V10의 설치 파일은 Codex CLI를 설치하지 않습니다.
- PPT 생성: 데스크톱 PowerPoint. 메일 발송: Classic Outlook 및 계정 설정.
- 네이버 계정으로 대상 카페 게시글을 읽을 권한. 각 사용자가 직접 로그인합니다.

**기존 RC1.7 사용자 업데이트**

1. 진행 중인 작업을 마친 뒤 V10 서버를 종료합니다.
2. 이 ZIP의 파일을 기존 V10 폴더에 덮어씁니다. `.venv`와 `data_v10`은 유지합니다.
3. `02_start_v10.bat` 실행 후 브라우저에서 Ctrl+F5를 눌러 제목을 갱신합니다.

2026-09-30 사용자 Windows에서 RC1.7 검사 75개 모두 통과(69.234초)를 확인했습니다. 같은 날 실제 실행 이력에는 카페 9개 완료·게시글 16건·PPT 30장·소요 30분 45초가 표시됐고, 같은 실행 ID의 PPT 첨부 메일을 Outlook 보낸 편지함에서 확인했습니다. '완료(일부 확인 필요)'의 구체적 사유와 전체 분석·PPT 내용의 품질은 이번 화면 확인 범위에 포함되지 않습니다.

최종 V10 HTML과 두 개발이력 문서를 기준으로 DB·API·실행 엔진을 연결한 Windows용 소스 패키지입니다. 운영 / 실행 이력 / 데이터 분석의 기존 화면 구성을 유지했습니다. 두 개발이력 문서는 내용이 동일했습니다.

Python 3.11 이상, 설치된 Chrome, 데스크톱 PowerPoint와 Classic Outlook을 사용합니다. AI는 기존 프로그램의 Codex CLI 또는 OpenAI API 설정을 이어받습니다. 기존 Python 소스는 V9.6.6 전달본에 V9.6.7 리팩터링 R2를 반영했습니다.

**처음 실행하는 순서**

1. ZIP을 새 폴더에 압축 해제합니다. 예: `C:\CafeMonitor\cafe_monitoring`.
2. `01_setup_v10.bat`를 실행합니다. 별도 Python 가상환경에 제공된 의존성을 설치하고 오프라인 검사를 수행합니다.
3. `02_start_v10.bat`를 실행합니다. 브라우저에서 `http://127.0.0.1:8766`이 열립니다. HTML을 직접 여는 방식이 아닙니다.
4. 처음 사용하는 분은 기존 V9 자료 이관을 건너뜁니다. 과거 V9 자료가 있는 사용자만 **DB 관리 → 기존 naver_cafe 폴더 → 기존 V9 자료 이관**에서 실제 사용 폴더를 연결합니다.
5. **네이버 로그인**을 누르고 전용 Chrome에서 직접 로그인한 뒤 그 Chrome 창을 닫습니다. API 방식은 기존 환경변수 키를 사용하거나 화면에 키를 입력할 수 있습니다. 입력한 키는 서버 메모리에만 보관합니다.
6. 카페·키워드·작업·PPT·메일 설정을 확인하고 **설정 저장 → 전체 실행**을 누릅니다. Outlook 발송은 기본 ON이므로 받는 사람을 입력해야 합니다.

기존 Python 가상환경을 바로 사용하려면, V10 폴더에서 기존 환경의 Python으로 `-m v10`을 실행할 수도 있습니다. 예:

```bat
"C:\기존프로그램\naver_cafe\.venv_v6\Scripts\python.exe" -m v10 --legacy-root "C:\기존프로그램\naver_cafe"
```

`--legacy-root`는 설정·프로필 연결입니다. 과거 자료 이관은 화면의 DB 관리에서 실행합니다.

**저장과 실행 방식**

| 항목 | 동작 |
|---|---|
| DB | 첫 실행 때 `data_v10/monitoring.sqlite3` 자동 생성 |
| 기본 결과 위치 | `data_v10/output_v10/실행ID/` |
| 실행 이력 | DB의 실제 실행·당시 설정·기간·단계·오류·파일 기록 |
| 게시글 | 카페 고정 ID + 게시글 ID로 구분, 네이버 숫자 카페 ID 연결 |
| 원문 변경 | 기존 원문 버전을 보존하고 새 버전 추가 |
| 기간 지정 중복 제외 | 같은 원문 제외, 변경된 원문 갱신, 새 키워드 매칭 관계는 보존 |
| 데이터 분석 | DB 누적 게시글을 사용하며 고유 게시글 수와 키워드 매칭 수를 구분 |
| 통계 날짜 | 최초 수집일(KST). 게시 시각은 게시글 상세에서 별도 확인 |
| 검토 완료 | 해당 원문 버전의 해당 분석에 저장. 원문이 바뀌면 이전 검토를 자동 승계하지 않음 |
| PPT | 기존 PowerPoint 엔진 사용. 전체 요약 1장 + 선택 카페별 요약, 카페별 요약 OFF이면 전체 1장 |
| PPT만 재생성 | 선택한 실행의 원문·분석·카페 요약 재사용, 추가 AI·재수집·메일 없음 |
| PPT 미리보기 | PowerPoint가 내보낸 실제 요약 슬라이드 PNG |
| 파일 열기 | 등록된 파일의 존재와 해시 확인 후 실행 |
| Excel | 적용된 조회 조건과 상세 선택으로 생성. 비교 그래프의 집계 범위를 조회 정보 시트에 명시 |
| 예약 | 저장한 설정, 한국시간, 주말 제외. V10 실행 창이 열려 있고 PC가 깨어 있는 동안 동작 |

웹 화면을 새로고침하거나 닫아도 별도 실행 프로세스는 계속됩니다. **V10 실행 콘솔을 종료하면** 예약 서비스가 종료됩니다. 다음 시작 때 중단된 작업을 기록하며 자동 재발송하지 않습니다. 종료 중인 작업이 남아 있으면 재시작을 잠시 기다리세요.

자동 수집은 현재 진행 중인 분을 제외하고 완료된 분까지 실행합니다. 예를 들어 13:29:54에 최근 24시간을 실행하면 전날 13:29:00부터 오늘 13:29:00 직전까지 수집합니다. 직접 지정은 분 단위 입력을 그대로 사용합니다.

수집 완료 시각은 카페별로 기록합니다. 한 카페 실패나 뒤의 AI·PPT·메일 실패 때문에 다른 카페의 수집 완료 기록을 지우지 않습니다. 기간을 직접 지정한 실행은 정규 수집 완료 시각을 바꾸지 않습니다.

메일의 `Outlook 전송 요청 수락`은 Outlook의 Send 요청 성공을 뜻합니다. 실제 배달 여부는 Outlook에서 확인합니다. 전송 중 종료·응답 유실은 `발송 확인 필요`로 남으며, 실행 이력에서 확인 결과를 기록할 수 있습니다. 이 확인 버튼은 메일을 다시 보내지 않습니다.

예약을 사용하기 전 기존 V9 예약 작업의 등록 상태를 확인하세요. V10이 기존 Windows 예약 작업을 변경하지는 않습니다. V10 자체 예약은 Windows 작업 스케줄러 등록 없이 동작하며, 서버가 꺼져 있는 동안 놓친 예약을 뒤늦게 자동 실행하지 않습니다.

**기존 자료 이관**

지원 범위는 기존 `output_v9/runs/*/run.json`, `output_v9/period/*/run.json`과 연결된 원문·분석·PPT입니다. V5 이력 DB, 단독 PPT 진단/재작성 폴더의 자동 이관은 포함하지 않습니다. 필요한 실제 PPT는 실행 이력의 `실제 PPT 연결`로 연결할 수 있습니다. 이 연결은 사용자가 지정한 파일이며, 해당 실행에서 생성됐다는 증명으로 취급하지 않습니다.

이관 전 DB 백업을 만들고, 같은 자료를 다시 지정하면 중복 이관을 건너뜁니다. 변경된 기존 기록은 별도 스냅샷으로 남깁니다. 원문이나 분석 해시가 맞지 않으면 확인된 자료로 가져오지 않고 제외 사유를 표시합니다. 수집 완료 시각도 과거 실행 자료만으로 자동 승계하지 않습니다. 처음에는 최근 24/48시간 수집을 실행하세요.

이번에 전달된 GPT용 V9 ZIP은 익명화된 인수인계본입니다. 시험 이관에서 2개 실행의 원문 58개 참조가 해시 검증에 실패했습니다. 안내문에도 익명화·경로 변경으로 재사용 보장이 없다고 명시되어 있습니다. **이관에는 실제 운영 PC의 원본 폴더를 사용하세요.** 이 패키지는 전달 ZIP의 게시글·캡처·PPT·계정 자료를 포함하지 않습니다.

**확인된 범위와 Windows 확인 항목**

초기 RC1에서 기존 엔진 검사 54개를 통과했으며, 이번 수정본은 Linux에서 V10 Python 검사 75개 중 74개 통과·Windows DPAPI 검사 1개 건너뜀, JavaScript 로직/API 계약 검사 49개 통과를 확인했습니다. 중복 실행 방지, 원문 버전, 검토 저장, 수집 완료 시각, 메일 불확실성, 이관 멱등성, 실제 HTTP API를 검사했습니다. 외부 수집·AI·Office 호출은 테스트 대역으로 분리했습니다.

개발 환경의 검사는 Linux에서 수행했습니다. 사용자 Windows에서는 RC1.7의 75개 오프라인 검사와 위 실제 실행·메일 화면을 확인했습니다. 정식 배포판은 제목·버전·안내만 갱신했으며, 그 변경본을 사용자 Windows에서 다시 실행한 결과는 아직 없습니다. 장시간 예약 및 새 PC의 최초 설치는 별도 확인 대상입니다. 수행 내역은 `docs/VALIDATION_KO.md`를 참고하세요.

소스 구조와 API는 `docs/ARCHITECTURE_KO.md`에 정리했습니다. DB 백업은 화면의 DB 관리에서 만들 수 있습니다. DB 백업 파일에는 PPT/캡처가 포함되지 않으므로 결과 폴더도 함께 보관하세요.
