# V10 10.0.0-rc1.2 추가 점검 및 수정

2026-09-30, RC1.1 이후 추가 오류 점검 결과입니다.

| 항목 | 재현한 오류 | 수정 |
|---|---|---|
| 실제 엔진 초기화 | 실행별 engine_config에 config_v5.json이 없어 JSON_READ_ERROR 발생. 실제 Backend와 설정 로더를 사용하여 재현했습니다. | 필수 설정 파일 복사 대상에 config_v5.json을 추가했습니다. |
| 기존 프로그램 설정 | 선택 항목인 request_interval_seconds를 생략하면 기본값이 들어가지 않아 KeyError 발생. 0 같은 잘못된 값도 기존 V9 검증을 거치지 않았습니다. | 기존 V9의 browser_config를 호출해 기본값 2초와 1~60초 검증, 원본 기준 경로 검사를 적용했습니다. 기존 파일을 수정하지 않습니다. |
| 수동 연결 PPT 열기 | linked_ppt로 등록했지만 열기 API는 ppt·summary_ppt만 허용해 HTTP 400 반환. 실제 로컬 HTTP 요청으로 재현했습니다. | linked_ppt를 열기 대상으로 포함했습니다. 변경·삭제된 파일의 해시·존재 검증은 유지했습니다. |

빈 게시글 목록에 남아 있던 '예시 게시글' 문구도 '표시할 수집 게시글'로 정리했습니다.

## 검사 범위

- V10 Python 39개 통과: 기존 33개에 6개 추가.
- 기본 파일 인코딩을 CP949로 모의한 전체 39개 검사 통과.
- JavaScript 로직/API 계약 19개 통과, Python 컴파일·JavaScript 문법 확인.
- 새 엔진 검사는 실제 V9 Backend, 설정 로더, 봉인된 수집 파일·원문 해시 검증을 사용합니다. 브라우저 접속·실제 AI 호출·PowerPoint·Outlook은 수행하지 않습니다.
- 파일 열기 검사는 실제 HTTP 서버에 요청하되 OS 실행 함수는 대역을 사용합니다. 실제 Windows 파일 열기 성공을 뜻하지 않습니다.
- 기존 54개 V9 검사는 RC1에서 수행한 기록입니다. 이번에는 V10 연결 부분을 수정했고 기존 엔진 코드는 변경하지 않았습니다.

RC1의 파이프라인 자동검사는 엔진을 시험용 대역으로 교체해 실행했기 때문에 실제 어댑터 초기화 오류를 잡지 못했습니다. 이번 검사에 그 경계를 추가했습니다. 검사 통과가 전체 Windows 동작의 정상 여부를 보장하지는 않습니다.

## 적용 순서

1. 실행 중인 V10 콘솔을 종료합니다.
2. ZIP의 naver_cafe_v10 안 파일들을 기존 같은 폴더에 덮어씁니다. 기존 .venv·data_v10 폴더는 유지합니다.
3. 03_verify_v10.bat를 실행해 Ran 39 tests 및 OK를 확인합니다.
4. 02_start_v10.bat로 시작합니다. 설정·DB 스키마는 변경되지 않았습니다.

남은 확인은 실제 Windows에서 네이버 수집, AI 분석, PPT 생성·미리보기, Outlook 발송 및 브라우저 화면 동작입니다. 이번 점검 결과로 다른 오류가 전혀 없다고 판단할 수 없습니다.
