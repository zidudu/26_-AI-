# V10 10.0.0-rc1.3 HTTP 거부 응답 수정

## 사용자 로그

2026-09-30에 받은 Windows / Python 3.14 검사 로그는 33개 중 32개 통과, 1개 오류였습니다. 잘못된 토큰·Origin을 검사하는 POST 요청에서 HTTP 403 대신 ConnectionAbortedError / WinError 10053이 발생했습니다. 새 RC1.2의 39개 검사 구성이 아니므로 최신 파일이 모두 적용된 상태는 확인되지 않았습니다.

이전 한글 인코딩·백업 DB 잠금·시험 파일 크기 검사 오류는 이번 사용자 로그에서 통과했습니다.

## 직접 재현한 사항

기존 서버는 요청 헤더를 거부하면 본문을 받기 전에 오류 응답 후 연결을 닫았습니다. 실제 로컬 TCP 연결에서 JSON 두 바이트를 나누어 보냈을 때, 본문이 아직 도착 중인데 서버가 먼저 닫는 것을 토큰·Origin 양쪽에서 재현했습니다.

이는 사용자 Windows의 10053을 직접 재현한 것은 아닙니다. HTTP 규격도 즉시 연결을 닫으면 뒤늦게 도착하는 데이터에 의해 TCP reset이 생겨 마지막 응답을 잃을 수 있음을 설명합니다. 참고: RFC 9112 §9.6, https://www.rfc-editor.org/rfc/rfc9112.html#section-9.6

## 수정

- 헤더 검증으로 거부한 요청은 선언된 본문을 최대 8 MiB·최대 2초 범위 안에서 읽어 버린 뒤 기존 오류를 반환합니다. 본문을 해석하거나 요청 동작을 실행하지 않습니다. 불완전한 본문을 무한 대기하지 않습니다.
- 토큰·Origin·Host 검증은 유지합니다. ConnectionAbortedError를 통과로 바꾸거나 실패를 재시도로 숨기지 않습니다.
- 127.0.0.1의 검사 요청만 시스템 프록시 자동 탐색 없이 직접 연결합니다. 회사 프록시·방화벽·보안 프로그램 설정은 변경하지 않습니다. 이는 검사 환경 분리이며 실제 프록시가 원인이었다는 판정은 아닙니다.
- 검사 실행 BAT가 실제 프로그램 버전과 기대 검사 수를 표시합니다.
- 기존 RC1.1·RC1.2의 모든 수정이 포함되어 있습니다.
