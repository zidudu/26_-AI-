# V10 10.0.0-rc1.7 — Codex 오프라인 검사 시간 초과 수정

## 확인한 원인

사용자가 보내주신 2026-09-30 16:30:43 진단은 Windows / Python 3.14.7 / 가상환경 / UTF-8 모드에서 실행됐습니다. 실제 OpenAI 로그인이나 AI 호출 없이 로컬 임시 CLI만 실행했습니다.

| 조건 | 결과 |
|---|---|
| RC1.6 검사, 상태 확인 제한 2초 | CODEX_TIMEOUT, 프로세스 정리까지 약 4초 |
| 같은 어댑터·임시 CLI, 제한 15초 | 2.970초, 종료 코드 0, ChatGPT 상태 문자열 확인 |
| 단순 subprocess·같은 임시 CLI, 제한 15초 | 2.953초, 종료 코드 0, ChatGPT 상태 문자열 확인 |
| 프로세스 생성 호출 자체 | 약 0.012~0.033초 |

정상적인 임시 CLI 실행이 검사 전용 2초 제한보다 오래 걸렸습니다. 전체 약 3초를 프로세스 생성 시간이라고 볼 수는 없습니다. 지연의 내부 원인이 Python 버전이나 보안 프로그램이라고 단정하지 않습니다. 이 결과는 실제 Codex 계정 인증의 성공 또는 실패를 뜻하지 않습니다.

## 수정

- `tests/test_codex_auth.py`의 정상 상태 확인에서 2초 강제 설정을 제거했습니다. 기존 엔진의 `CodexOptions.preflight_timeout_seconds` 기본값인 30초를 그대로 사용합니다.
- 비동기 검사 완료 대기를 기존 5초에서 위 설정 + 정리 여유 10초, 현재 40초로 조정했습니다. 고정 시간 동안 항상 기다리는 것이 아니라, 작업이 끝나면 즉시 진행합니다.
- 상태만 비교하던 판정을 상태·오류 코드·작업 종료 여부로 보강했습니다. CLI 오류는 `CODEX_STATUS_FAILED`여야 하며, 시간 초과를 일반 오류 검사 성공으로 처리하지 않습니다.
- 중복 로그인 클릭 검사도 로그인 프로세스가 한 개라는 조건뿐 아니라 최종 `connected` 상태까지 확인합니다.
- 실패 시 공개 상태와 오류 코드를 검사 메시지에 표시합니다. CLI 원문 출력이나 인증값을 출력하지 않습니다.
- 3초 지연 회귀검사 1개를 추가했습니다. 같은 임시 CLI를 2초 제한으로 실행하면 `CODEX_TIMEOUT`, 실제 엔진 기본 제한으로 실행하면 `connected`가 되는 것을 확인합니다.
- 기존 0.1초 상태 확인 시간 초과 검사와 0.05초 로그인 시간 초과 검사는 유지했습니다.

앱의 버전 표시는 RC1.7로 갱신했습니다. 실제 Codex 인증 코드, 기존 엔진의 30초 제한, 수집·DB·UI 동작은 RC1.6과 같습니다. 별도 의존성 추가는 없습니다.

## 검증

- Linux / Python 3.12: 전체 75개 중 74개 통과, Windows DPAPI 1개 건너뜀. `docs/runtime_tests.log`에 결과를 담았습니다.
- Codex 관련 10개 검사 통과. 실제 자식 프로세스를 쓰는 로컬 CLI 대역 검사이며, 실제 OpenAI 로그인은 수행하지 않았습니다.
- JavaScript 로직/API 계약 49개 통과. Python 컴파일·JavaScript 문법 검사 통과.
- 기존 `engine/` 파일은 RC1.6 배포 ZIP과 바이트가 같습니다.
- RC1.7의 사용자 Windows 검사 및 실제 Codex 로그인·AI 응답은 아직 확인하지 않았습니다.

## 적용

1. 작업을 마친 뒤 V10 실행 콘솔을 닫습니다.
2. ZIP 안 `naver_cafe_v10`의 파일을 기존 같은 폴더에 덮어씁니다. `.venv`와 `data_v10`은 유지합니다.
3. `03_verify_v10.bat`를 실행합니다. 첫머리 `V10 10.0.0-rc1.7 / expected tests: 75`, 마지막 `Ran 75 tests` 및 `OK`를 확인합니다.
