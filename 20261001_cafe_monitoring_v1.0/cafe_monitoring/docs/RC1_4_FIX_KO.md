# V10 10.0.0-rc1.4 수집 기간 및 로그인 표시 수정

## 확인된 문제

사용자 Windows / Python 3.14에서 RC1.3의 42개 오프라인 검사는 모두 통과했습니다. 이후 실제 실행에서 9개 카페 모두 “시작은 종료보다 빨라야 하며 분 단위로 지정해야 합니다” 오류로 중단됐습니다.

V10 자동 기간 계산은 실행 시각의 초를 유지했지만, 기존 엔진의 Window는 시작·종료의 초와 마이크로초가 모두 0인 기간만 허용했습니다. 수정 전 실제 Service.period에 2026-09-30 13:29:54.123456 KST를 넣고 기존 Window로 전달하여 동일한 오류를 재현했습니다. 이 오류는 로그인 실패를 뜻하지 않습니다.

기존 로더 연동 검사는 시작과 종료를 직접 00초로 지정해 실제 실행 시각에서 생기는 이 불일치를 놓쳤습니다. 해당 검사가 V10의 실제 기간 계산을 거치도록 변경했습니다.

## 변경 사항

- 최근 24/48시간과 이전 실행 이후의 종료를 현재 분의 00초로 내립니다. 진행 중인 분은 이번 수집에서 제외됩니다.
- 실행 기록을 만들기 전에 기간을 확정하므로 DB 기록, 엔진에 전달하는 기간, 성공한 카페의 다음 시작점이 일치합니다.
- 이전 완료 시각에 초가 들어 있으면 분 시작으로 내립니다. 일부를 다시 확인할 수 있지만 초를 올려 수집 구간을 건너뛰지는 않습니다.
- 같은 분 안에서 중복 확인 기간 0으로 다시 실행해 수집 구간이 비면 브라우저를 열기 전에 안내합니다.
- 직접 지정한 정상 분 단위 기간은 유지합니다. 초·마이크로초가 있는 직접 지정은 실행 기록 생성 전에 오류를 안내합니다.
- 화면의 예상 기간도 서버와 같은 분 단위를 사용합니다.
- 로그인 세션이 저장되면 하단 표시가 즉시 초록색으로 바뀝니다. 실제 카페 접근 확인 전에는 “로그인 세션 저장됨 · 수집 시 접근 확인” 문구를 유지합니다.
- RC1.1~RC1.3의 인코딩·DB 백업·엔진 설정·PPT 연결·HTTP 거부 응답 수정이 포함됩니다.

## 검증

- Linux / Python 3.12: V10 검사 47개 통과. 신규 5개 기간 검사가 포함됩니다.
- Node 24: JavaScript 로직/API 계약 26개 통과. 기간 정밀도와 로그인 상태별 CSS 클래스 전환을 포함합니다.
- 실제 기존 엔진의 Window·수집 파일 저장·로더 검사를 V10의 초가 있는 실행 시각에서 시작해 통과했습니다. 브라우저 수집은 대역입니다.
- 사용자 Windows에서 RC1.4의 실제 수집 성공은 아직 확인 전입니다. 오프라인 검사 통과를 네이버·AI·Office 성공으로 해석하지 않습니다.

## 적용

1. 수집/로그인 전용 Chrome과 V10 실행 콘솔을 종료합니다.
2. ZIP의 naver_cafe_v10 안 파일을 기존 naver_cafe_v10 폴더에 덮어씁니다. 기존 data_v10·.venv는 삭제하지 않습니다.
3. 03_verify_v10.bat에서 `V10 10.0.0-rc1.4 / expected tests: 47`, `Ran 47 tests`, `OK`를 확인합니다.
4. 02_start_v10.bat를 실행하고 기존 V10 페이지는 Ctrl+F5로 새로고침합니다.
5. 로그인 세션 저장 표시가 초록색인지 확인하고 수집을 다시 실행합니다. 최초 확인은 카페 1개·최근 24시간·수집만으로 진행할 수 있습니다.
