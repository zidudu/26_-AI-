**실제 사용자 Windows / Python 3.14의 초기 RC1 설치 검사는 31개 중 실패 1회·오류 6회로 끝났습니다.** 패키지 설치는 성공했고, 오류 중에는 동일 검사 실행과 정리 단계에서 각각 발생한 항목이 있습니다. 이번 수정은 해당 로그를 기준으로 했습니다. CP949 조건 검사는 Linux에서 기본 텍스트 파일 인코딩을 바꾼 재현 검사이며 Windows 파일 잠금·실제 PPT 처리를 실행한 결과가 아닙니다.

검사는 외부 AI 호출이나 메일 발송을 수행하지 않습니다. V10의 파이프라인 시험에서는 명시적인 수집·Office 테스트 대역을 사용했습니다. 이는 실제 PPT 파일 생성이나 실제 메일 전송의 성공 증거가 아닙니다.

RC1.2에서는 실제 V9 엔진 초기화, 기존 설정의 요청 간격 기본값·잘못된 값 검증, 봉인된 수집 파일의 실제 로더 연결, 수동 연결 PPT 열기·변경 파일 거부 검사를 추가했습니다. Windows 플랫폼 검사, 브라우저 접속, OS 파일 열기 부분은 대역을 사용했습니다.

RC1.3 추가 검사: 분할 전송된 거부 요청의 본문 처리, 불완전 본문의 제한 시간, 로컬 검사에서 시스템 프록시 자동 탐색 미사용. WinError 10053 자체는 Linux에서 재현하지 못했습니다. 이후 사용자 Windows / Python 3.14에서 RC1.3의 42개 검사 모두 통과(9.955초) 로그를 받았습니다.

RC1.4는 실제 V10 기간 계산값을 기존 엔진의 Window 및 저장 결과 로더에 연결했습니다. 수정 전 13:29:54.123456 실행으로 동일한 분 단위 오류를 재현했고 수정 후 통과했습니다. 추가 Python 5개 검사는 24/48시간의 DB·완료 시각 일치, 초가 있는 이전 완료 시각의 안전한 내림, 같은 분 재실행의 사전 거부, 직접 지정 초 입력의 사전 거부, 직접 지정 분 입력 보존을 확인합니다. JavaScript에는 기간 정밀도 3개와 로그인 상태 전환 4개 검사를 추가했습니다. 로그인 성공의 초록색 CSS 클래스와 문구를 확인했으며 실제 화면 렌더링 검사는 아닙니다.

사용자 실제 환경에서는 RC1.3 로그인 세션 저장은 확인됐지만 9개 카페 수집이 기간 검증에서 중단됐습니다. 이후 사용자 Windows에서 RC1.4의 47개 검사 모두 통과(10.607초)했습니다. 실제 실행은 검색 화면까지 진행됐지만 재로그인 창과 PPT OFF 상태의 PowerPoint 창이 관찰됐습니다. RC1.5에서 세션 재사용·수집 전 로그인 검사·로그인 팝업 중단과 PPT OFF 시 캡처 실측 생략을 반영했습니다. 이후 RC1.5에 대한 사용자 확인 결과는 아래 최신 증거에 구분해 기록했습니다.

RC1.5 추가 검사: 로그인과 수집의 프로필/브라우저/잠금 일치, 실제 Backend.collect_async→캡처 최적화 경로의 PPT ON/OFF 분기, 로그인 창 종료 후 세션 전달(모의 브라우저), 세션 누락·만료·다른 프로필·암호화 실패, 로그인 팝업의 요청 중단/상태 갱신, 비밀값의 DB/API/로그 미노출. Windows DPAPI 왕복 검사는 Windows에서만 실행됩니다. JavaScript 추가 검사는 로그 위치, 상태 문구, 상태 변경 없는 동안의 실시간 로그 조회 및 마지막 로그 번호 재사용을 확인합니다. 실제 브라우저 화면 렌더링 검사는 아닙니다.

**Windows에서 처음 확인할 순서**

1. `02_start_v10.bat`로 페이지를 열고 운영/실행 이력/데이터 분석, 라이트/다크 모드와 창 크기를 확인합니다.
2. 실제 V9 원본 폴더를 연결하고 이관 결과의 성공·제외 사유를 확인합니다. 이관 전 DB 백업이 생성됩니다.
3. 첫 실제 실행에서는 작은 범위와 한 카페로 원문·캡처 저장, 네이버 접근 상태를 확인합니다. 테스트 발송이 불필요하면 Outlook 발송을 끕니다.
4. AI 분석의 원문·근거·검토 목록을 확인합니다. 검토 완료 후 새로고침하여 상태가 유지되는지 확인합니다.
5. PPT를 열어 글꼴, 실제 이미지 PPI, 원문 노트, 그래프·요약 장수, 상세 보기 링크를 확인합니다. 시안 이미지 대신 실제 PPT 이미지가 표시되는지 확인합니다.
6. 같은 실행의 PPT만 재생성하여 추가 AI·수집·메일이 없고 새 결과 폴더에 저장되는지 확인합니다.
7. 사용자가 지정한 수신자로 Outlook 발송과 요약본을 확인합니다. 전송 요청 성공과 실제 배달을 구분합니다.
8. 서버를 켠 상태로 예약 시각·주말 제외·다른 작업과 겹친 경우를 확인합니다. 기존 V9 예약도 확인합니다.
