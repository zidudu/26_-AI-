# 2.1.0 북마크

작업일: 2026-09-28 KST.

## 사용법

미디어 카드와 확대 화면에서 이미지 하나 또는 그 이미지가 속한 글을 각각 북마크합니다. 게시글 목록과 상세 화면에서도 글을 북마크할 수 있습니다. `☆`는 미등록, `★`는 등록 상태이며 다시 누르면 해제됩니다. 같은 글의 여러 카드와 확대 화면의 상태도 함께 바뀝니다.

북마크 탭(`/bookmarks`)은 이미지 격자입니다. 글은 수집된 본문 이미지/GIF를 우선 표지로 사용하고 동영상도 표시합니다. 미디어 북마크는 사용자가 선택한 파일을 사용합니다. 텍스트 글과 아직 미수집인 파일은 안내 카드로 남깁니다.

| 필터 | 동작 |
|---|---|
| 저장 대상 | 글 + 미디어 / 글만 / 미디어만 |
| 미디어 종류 | 이미지 / GIF / 동영상 / 아카콘 / 외부 미디어 |
| 채널 | 사이트가 함께 표시되는 채널 선택 |
| 검색 | 글의 제목·본문·작성자에서 부분 문자열 검색 |
| 정렬 | 최근 북마크순 / 오래된 북마크순 |

필터는 조합할 수 있고 페이지 이동 시 유지됩니다. 글에 종류 필터를 적용하면 그 종류를 포함하는 글을 찾고 해당 미디어를 표지로 표시합니다. 초기화는 필터를 모두 해제합니다. 검색 결과가 없는 경우와 북마크 자체가 없는 경우를 구분합니다.

## 저장과 변경 범위

- 스키마 5 → 6: `bookmarks` 테이블과 정렬 인덱스 추가. 글 또는 미디어 중 정확히 하나를 참조하며 중복 등록을 막습니다.
- 저장/해제 API: `PUT /api/bookmarks/{article|media}/{id}`, JSON `{"saved": true|false}`. 동일 요청을 반복해도 중복되지 않습니다. 응답 성공 후에만 UI 상태를 바꿉니다.
- 파일 복사·추가 다운로드·수집 상태 변경 없음. 원본 URL 갱신이나 재수집 후에도 기존 미디어 ID를 따라갑니다.
- DB 재연결과 기존 백업/복원 도구로 북마크가 유지됩니다. 사용자가 해당 글·미디어·채널 자체를 삭제하면 관련 북마크도 함께 정리됩니다.
- 북마크는 특정 시점의 별도 사본이 아니라 현재 보관된 글/파일에 대한 참조입니다. 다운로드 대기 파일은 수집이 완료되면 썸네일이 나타납니다.

## 검증

- 전체 자동 테스트 123개 통과. 추가 8개는 중복·독립 해제·재연결 지속성, 미수집 참조, 입력 검증, 삭제 정합성, 복합 필터·페이지 이동·대표 미디어, 안전한 문자열 렌더링, 스키마 이행을 확인합니다.
- 기존 백업/복원 테스트에 글·미디어 북마크 보존 검증 추가.
- 실제 DB 백업의 복사본을 이행하여 기존 9개 테이블의 모든 행을 SHA-256으로 비교: 동일. quick_check 및 foreign_key_check 정상. 글 16,150개, 미디어 42,193개, 댓글 61,086개, 채널 5개는 이행 시험에 사용한 백업 시점의 수치입니다.
- Python 컴파일과 `git diff --check` 통과. 기존 FastAPI/Starlette 사용 중단 예고 경고 2개는 별도 변경하지 않았습니다.
- Chrome/Playwright: 미디어 카드 → 확대 화면 → 이미지·원문 글 북마크 → 게시글 목록·상세 → 북마크 필터 → 해제까지 9개 시나리오 통과. 1440px 데스크톱 / 390px 모바일 화면 캡처를 육안 확인했습니다.
- 동영상 재생, 필터 결과의 마지막 파일 해제, 확대 중 현재 이미지 해제 후 이동, 서버 오류 응답 시 상태 보존 및 재시도, 원본 파일 해시 불변을 확인했습니다. 예상한 오류 응답 1건을 제외한 콘솔 오류·경고, 페이지 오류, HTTP 오류는 0건입니다.
- 브라우저 시험은 실제 템플릿·JS·CSS와 FastAPI TestClient를 연결한 독립 데이터에서 수행했습니다. 별도 웹서버를 시작하거나 운영 크롤러의 Chrome 프로필을 사용하지 않았습니다. 설치된 전용 Browser plugin이 없어 기존 Python Playwright/Chrome을 사용했습니다.
- 최종 접근성 조정 후 관련 테스트 15개와 브라우저 9개 시나리오를 다시 확인했습니다. 확대 화면에서는 배경 포커스를 막고 닫으면 원래 위치로 돌립니다.

검증 자료: `로컬 QA 임시 폴더` (`migration.json`, `pytest.txt`, `browser-report.json`, 화면 캡처).

## 백업과 적용

변경 전 소스 및 온라인 SQLite 백업: `data/backups/bookmarks-20260928-123923/`.

사용자가 서버를 재시작한 뒤 운영 주소 `http://127.0.0.1:8766`에서 **2.1.0 / 스키마 6 적용 완료**를 확인했습니다. 기존 수집 설정과 채널 활성화 상태는 그대로입니다.

적용 준비: 운영 서버 2.0.0 확인, 원래 자동 수집 상태 `켜짐` 기록 후 스케줄러를 일시 정지하고 실행 중 수집을 정상 중지했습니다. 현재 작업·대기열이 비어 있음을 확인한 뒤 사용자에게 재시작을 요청했습니다. 이전 자동 승인 검토의 서버 프로세스 종료·시작 차단을 우회하지 않았습니다.

운영 확인: 실제 보관 중인 디시 글 1개와 이미지 1개를 API로 북마크하고, 북마크 목록·복합 필터·본문·미디어·게시글 목록의 HTTP 200 및 저장 상태를 확인했습니다. 시험 북마크는 즉시 해제하여 최종 시험 항목 0개를 확인했습니다. 시험 원본 파일의 바이트는 동일하고 `quick_check=ok`, 외래키 오류 0개입니다. 최종 자동 수집은 켜져 있고 실제 수집 실행 중입니다. 기록: 검증 자료 폴더의 `live-acceptance.json`.
