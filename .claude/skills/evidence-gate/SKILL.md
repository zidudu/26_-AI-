# 검증 우선 수집

외부 자료를 많이 모으는 대신, 사용자가 실제로 믿고 써볼 가치가 있는 후보를 선별하라. 자료의 종류와 잘못 선택했을 때의 비용에 맞춰 검증 방법과 깊이를 조절하라.

## 핵심 원칙

- 발견을 검증으로 취급하지 말라.
- 인기, 조회수, 별점, 다운로드 수를 신뢰성의 보조 신호로만 사용하라.
- 동일 원본을 되풀이한 여러 글을 독립된 검증으로 세지 말라.
- 제작자의 자체 주장과 제3자의 재현 결과를 구분하라.
- AI가 만든 요약이나 판단을 원자료의 증거로 순환 인용하지 말라.
- 검증 부족을 곧바로 폐기 사유로 삼지 말고, 실험 후보로 분류해 위험을 제한하라.
- 충분한 근거가 모이면 의사결정에 영향을 주지 않는 추가 조사를 멈추라.
- 추천은 제공하되 최종 채택 권한은 사용자에게 남겨라.

## 검증 강도 조절

먼저 실패의 영향, 되돌리기 쉬운 정도, 비용, 최신성 요구를 판단하라.

- 단순 참고나 쉽게 되돌릴 수 있는 실험은 핵심 출처와 명백한 위험만 빠르게 확인하라.
- 실제 작업에 도입할 코드, 도구, 데이터 또는 방법은 원본 자료와 독립된 사용·시험 신호를 확인하고, 가능하면 작은 범위에서 직접 재현하라.
- 안전, 건강, 법률, 재무, 개인정보, 생산 시스템처럼 실패 비용이 큰 결정은 최신 권위 자료, 독립된 근거, 적용 조건과 한계를 더 엄격하게 교차 검증하라.

검증 횟수를 기계적으로 채우지 말라. 공식 문서와 직접 시험으로 충분할 수 있고, 이해관계가 있는 벤치마크 여러 개보다 독립적인 재현 한 번이 더 강할 수 있다.

## 조사와 판정 절차

1. 사용 목적과 필수 조건을 파악하라. 운영체제, 버전, 하드웨어, 예산, 라이선스, 통합 대상과 허용 가능한 위험을 포함하라. 빠진 정보가 결론을 크게 바꾸지 않으면 합리적인 가정을 밝히고 진행하라.
2. 원본 출처를 추적하라. 재인용보다 공식 문서, 원 논문, 원 저장소, 원 데이터와 실제 릴리스를 우선하라.
3. 후보마다 가장 판별력 높은 근거를 선택하라. 모든 후보에 같은 체크리스트를 강요하지 말라.
4. 독립성을 확인하라. 누가 누구를 인용했는지 추적하고, 실제로 별개의 시험·사용·관측인지 판단하라.
5. 실행 가능한 대상은 안전한 최소 시험으로 확인하라. 문서상의 주장, 타인의 결과, 현재 환경에서 직접 관찰한 결과를 명확히 구분하라. 외부 시스템 변경이나 비용·위험이 있는 시험은 기존 권한 범위를 넘지 말라.
6. 사용자 환경 적합성을 비교하라. 객관적으로 우수한 후보라도 현재 목적과 호환되지 않으면 우선순위를 낮추라.
7. 남은 불확실성이 선택에 미치는 영향을 평가하고 채택, 제한적 시험, 보류 또는 제외를 추천하라.

## 자료별로 볼 만한 근거

상황에 맞는 항목만 선택하라.

- 소프트웨어와 GitHub: 실제 릴리스, 최근 유지보수, 테스트와 CI, 해결·미해결 이슈, 보안 공지, 의존성, 라이선스, 설치 재현, 운영 사용 사례
- 논문과 기술 주장: 연구 설계, 데이터와 코드 공개 여부, 동료평가, 후속 연구, 독립 재현, 반대 결과, 적용 범위와 한계
- 데이터셋과 수치: 수집 주체, 원천, 표본과 기간, 정의, 결측·편향, 변경 이력, 다른 자료와의 교차 확인
- 제품과 서비스: 공식 사양, 최신 가격과 정책, 장기 사용 사례, 독립 시험, 반복되는 고장·제약, 지원과 유지 비용
- 설치법과 자동화: 대상 버전, 실제 성공 기록, 필요한 권한, 실패 시 복구 가능성, 현재 환경의 최소 재현
- 프롬프트와 방법론: 비교 기준, 반복 실행 결과, 실패 사례, 다른 조건에서의 성능, 사용자의 실제 목적에 대한 개선 여부

## 충돌과 불확실성 처리

출처가 충돌하면 다수결로 고르지 말라. 자료의 날짜, 원본성, 측정 방법, 표본, 이해관계, 적용 환경과 독립성을 비교하라. 해소되지 않은 충돌은 숨기지 말고 어떤 추가 확인이 결론을 바꿀 수 있는지 제시하라.

검증할 방법이 없으면 “검증됨”이라고 표현하지 말라. 확인된 범위와 미확인 범위를 나누고, 안전한 소규모 시험 또는 대체 후보를 제안하라.

## 결과 전달

사용자가 빠르게 결정할 수 있게 필요한 밀도로 정리하라. 후보가 여러 개면 비교표를 우선하고, 단일 후보면 짧은 판정 형식을 사용하라.

각 후보에 다음을 포함하라.

- 무엇이며 현재 목적에 왜 관련되는지
- 확인된 근거와 그 근거의 독립성
- 직접 확인한 결과와 타인의 주장
- 사용자 환경에 맞는 점과 맞지 않는 점
- 알려진 위험, 한계와 아직 모르는 사항
- 판정: 채택 추천, 소규모 시험 후 채택, 보류 또는 제외

사실, 직접 관찰, 추론, 추천을 서로 혼동하지 말라. 웹이나 외부 자료를 사용했다면 사용자가 원문을 확인할 수 있도록 핵심 주장 가까이에 출처를 연결하라.

## 최종 점검

답을 내기 전에 다음을 확인하라.

- 이 근거는 원본인가, 복사된 주장인가?
- 실제 시험이나 독립적인 확인이 한 번이라도 존재하는가?
- 존재한다면 사용자의 조건과 충분히 비슷한가?
- 최신 버전과 현재 날짜에도 유효한가?
- 직접 확인한 것과 추론한 것을 구분했는가?
- 더 조사하면 실제 선택이 달라질 가능성이 있는가?

가장 중요한 기준은 다음과 같다.

> 가능하면 검증된 것을 우선하고, 검증되지 않은 것은 작은 시험으로 다룬다. 검증 방법 자체도 상황에 맞게 바꾼다.
