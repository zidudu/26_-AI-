## 2. 실제 업로드 영상 변환

사용자가 제공한 `Spring Never Reaches Here` MP4 전체를 사용했습니다.
단순 synthetic 영상의 결과가 아닙니다. ffprobe 원본 정보:

```text
길이       116.680272초
원본 영상  VP9 / 2560×1440 / 60fps
원본 오디오 AAC
원본 크기  116,720,328 bytes
720p 결과  13,462,479 bytes
480p 결과  5,850,737 bytes
```

이 원본에 한해 GUI 표기 기준 약111.3MB → 12.8MB/5.6MB입니다.
여기서 MB는 GUI의1024² 기반 환산(MiB 상당)입니다. 모든 영상의 압축률이 같다는 뜻이 아닙니다.
720p 변환62.98초, 480p 작업50.72초가 이 환경에서 관측됐지만 PC별 처리 시간 보장은 아닙니다.
원본은 읽기만 하였고 파일을 바꾸거나 삭제하지 않았습니다.

480p는 단독 함수 호출뿐 아니라 **실제 HTTP POST → Manager → 별도 worker 프로세스 → 등록 → 인증된 Range206** 경로로도 실행했습니다.
응답은 bytes0-127에206/128바이트를 반환했습니다. 새 미디어 파일로 확장만 바꾼 것이 아니라 실제 인코딩 결과입니다.

## 4. 브라우저 동작 및 화면 검사

Browser 플러그인이 없어 Playwright + 시스템 Chromium을 사용했습니다.
관리된 Chromium이 localhost 및 테스트 도메인 상위 탐색을 `ERR_BLOCKED_BY_ADMINISTRATOR`로 거부했습니다.
정책을 변경하거나 해제하지 않았습니다.

대신 about:blank의 테스트용 하네스에 프로젝트의 HTML/CSS/JS 원문을 인라인으로 렌더링했습니다.
fetch는 실제 실행 중인 FastAPI 서버에 httpx로 연결했고, 재생 파일은 동일한 인코딩 결과를 Blob으로 연결했습니다.
SSE는 UI 하네스에서 서버의 실제 요약을 전달하는 대체 transport이며, 네이티브 EventSource 연속 전송은 위의 별도 HTTP 검사와 분리했습니다.

따라서 이것은 **실제 코드의 DOM/상호작용 검사**입니다. 네이티브 브라우저의 HTTP/HTTPS/CSP/Range 전송,
실제 기기의 네트워크 지연과 버퍼링을 모두 확인한 종단 간 브라우저 시험으로 주장하지 않습니다.
인증된HTTP/Range/304/SSE프로토콜은 앞의API·실제서버검사로 따로 검증했습니다.

확인 화면: 데스크톱1440×1000, 모바일390×844.
모바일은 원격 Host/Origin을 넣은 인증된 서버 응답으로 확인하여 PC전용버튼숨김도 검사합니다.
