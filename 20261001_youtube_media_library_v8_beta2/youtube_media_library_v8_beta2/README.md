# YouTube Media Library V8 beta.2 — Performance

PC 서버 + 모바일/PC 웹 라이브러리의 성능 개선판입니다.
로그인, 30일 자동 로그인, 태그·즐겨찾기, TXT, 영상/음원, 여러 URL·재생목록, 작업 대기열을 유지합니다.

공유 ZIP을 처음 받은 경우 [SHARE_START.md](SHARE_START.md)의 설치 순서부터 확인하세요. Chrome 확장은 `chrome_extension`, AI 연결용 MCP 서버는 `ai_plugin`에 포함되어 있습니다.

`run_v8.bat` 또는 `run_v8_beta.bat`을 실행하면, 자동 시작으로 이미 켜진 서버가 정상 응답하는 경우 해당 서버의 화면만 엽니다. 서버를 중복 실행하지 않으며, 성공 후 BAT 창은 자동으로 닫힙니다. 서버가 아직 없으면 기존처럼 서버를 시작합니다.

## 2026-10-01 화면 및 태그 보수

영상은 비율을 유지하면서 가용 너비에 맞춰 표시합니다. `큰 화면`을 누르면 자료 목록도 접혀 재생 공간이 넓어지고, 목록·재생·자막·빠른 URL 입력은 각각 접을 수 있습니다. 좁은 PC 화면(651~900px)에서는 자료를 고르면 목록을 자동으로 접습니다. 선택한 자료의 다운로드 링크는 제목 바로 아래에 있으며, 상세 파일 목록은 타임스탬프 위에 있습니다. MKV 등 브라우저 재생이 어려운 원본만 있을 때는 자동 품질에서 모바일 720p 재생본 생성을 안내합니다. 원본 다운로드는 바로 가능합니다.

태그는 `태그 추가` 버튼 또는 Enter로 저장하고 성공 메시지를 표시합니다. 잘못된 복수 태그 입력은 전체 변경을 거부합니다. 새 기능을 추가할 때의 수정 지점과 점검 방법은 [EXTENDING.md](EXTENDING.md)에 정리했습니다.

**이 버전은 이미 쓰고 있는 Funnel 443 연결을 그대로 사용합니다.**
선택적으로 Tailscale 내부의 개인 HTTPS 8443 경로를 추가할 수 있습니다.
코드 변경만으로 Funnel의 대역폭 제한이나 집 인터넷 업로드 속도가 바뀌는 것은 아닙니다.

## 기존 beta.1 사용자의 업데이트 — 먼저 이것만 하세요

1. **현재 설치 폴더의 `stop_v8_beta.bat`**으로 서버를 정상 종료합니다. 수집·변환 중인 작업은 먼저 완료하거나 취소하세요.
2. 서버 종료 후 `config` 폴더와 실제 DB 폴더의 `library.sqlite3`를 다른 안전한 폴더에 백업합니다. 사용자 지정 DB 경로를 쓰면 그 경로의 DB입니다. 설정/인증 파일은 외부에 공유하지 마세요.
3. ZIP 안의 내용을 **기존 beta.1 설치 폴더에 덮어씁니다.** `config`, `data`, `output`, `.venv`는 삭제하지 마세요. ZIP에는 이 사용자 폴더들이 포함되어 있지 않습니다.
4. **기존과 같은 `run_v8_beta.bat`**을 실행합니다. 첫 실행은 추가 패키지 Pillow 설치로 시간이 걸릴 수 있습니다.
5. PC 브라우저는 `Ctrl+F5`, 휴대폰은 탭 새로고침 후 다시 엽니다. 제목/서버 연결 창에서 `V8 beta.2`를 확인하세요.

계정과 기존 HTTPS 주소를 다시 만들 필요가 없습니다. **기존 Funnel 이용자는 02번을 다시 실행하지 마세요.**
실수로 실행해도 443의 Funnel 설정이 확인되면 중단하고 05번을 안내하도록 보호했습니다.

기존 자동 시작 작업은 설치 폴더와 BAT 이름을 바꾸지 않았으면 그대로 사용합니다.
새 패키지를 별도 폴더에 풀고 기존 자동 시작은 옛 폴더를 가리키게 두는 방식은 피하세요.

## 모바일 영상 재생 — 기존 영상은 한 번 준비가 필요합니다

기존 원본을 열었다고 모든 파일을 자동으로 변환하지는 않습니다.

1. 모바일에서 자료를 선택합니다.
2. `재생 품질`의 기본 `자동`은 모바일/외부에서 **모바일 720p**를 선택합니다.
3. 재생본이 없으면 **`모바일 720p 만들기`**가 나옵니다. 누르면 서버의 작업 대기열에 추가됩니다.
4. **변환이 끝난 뒤 재생 버튼을 다시 누릅니다.** 브라우저의 자동 재생 권한과 무관하게, 완료 직후 강제 재생하지 않습니다.
5. 여전히 연결이 느리면 **`절약 480p · 느린 연결`**을 선택해 재생본을 준비합니다.

처음 변환하는 동안 CPU와 추가 저장공간을 사용합니다. 변환 중 대기와 영상 재생 중 버퍼링은 구분하세요.
같은 원본/프로필의 완성된 재생본은 다음부터 재사용합니다. 원본 크기·수정 시각이 바뀌면 이전 재생본을 유효한 것으로 제공하지 않습니다.

### 원본과 모바일본 다운로드

플레이어 아래에 **선택 파일 용량**과 **원본 용량**을 따로 표시합니다.
외부에서는 작은 모바일 파일을 받으면 전송할 바이트 수가 줄어듭니다.
`원본` 다운로드는 원래 크기 그대로이므로 여전히 네트워크에 따라 느릴 수 있습니다.

### 새 영상 / 여러 기존 영상

수집 설정의 **`모바일 재생본 자동 생성`**은 기본 체크입니다. 새 영상 수집 후 720p를 생성합니다.
원본 수집만 빨리 끝내려면 체크를 해제하세요. 영상이 없는 자막/음원 전용 모드는 변환하지 않습니다.

**서버 연결 → 현재 목록의 모바일본 준비 (최대 20개)**로 기존 자료를 순차 변환할 수도 있습니다.
선택한 필터의 현재 로드된 자료 중 영상이 있는 첫 20개가 대상입니다. 전체 DB를 무조건 변환하지 않습니다.
썸네일·재생본 캐시는 서버 설정의 DB/data 폴더 아래에 있습니다. 원본 영상은 제자리에 남습니다.

## 영상 프로필

| 항목 | 모바일 720p | 절약 480p |
|---|---|---|
| 최대 크기 | 1280×720 범위, 종횡비 유지 | 854×480 범위, 종횡비 유지 |
| 프레임 | 30fps | 30fps |
| 코덱 | H.264 High / yuv420p | H.264 High / yuv420p |
| 영상 VBV maxrate | 1,600 kbps | 800 kbps |
| 오디오 | AAC 스테레오 96 kbps | AAC 스테레오 64 kbps |
| MP4 | faststart | faststart |

영상 maxrate는 인코더 버퍼 기준의 설정이지 매 순간의 HTTP 속도/완성 파일 크기를 보장하는 수치는 아닙니다.
CRF + VBV 방식이며, 원본보다 화질이 낮아질 수 있습니다. 작은 원본을 억지로 확대하지 않습니다.
이번 버전은 **고정 프로필 MP4**입니다. HLS나 네트워크에 따른 실시간 자동 품질 변경은 넣지 않았습니다.
HDR 톤매핑, 모든 코덱/브라우저/가변 프레임레이트 영상의 호환성을 보장하지 않습니다.
FFmpeg는 두 스레드, 단일 작업 큐로 실행하고 실패한 임시 파일은 정리합니다.

## 선택: 개인 연결 8443 추가

현재 공개 주소로 계속 사용할 수 있습니다. 원본 영상 전송을 자주 사용할 때 별도 개인 경로를 추가할 수 있습니다.

1. **서버 PC에서 `05_connect_private_fast.bat`** 실행.
2. 표시된 주소/대상을 확인하고 `y`로 동의.
3. 도우미가 기존 443 설정을 백업하고 **Serve 8443만 추가**합니다. 443 보존을 확인한 뒤 설정에 주소를 저장합니다.
4. `stop_v8_beta.bat` → `run_v8_beta.bat`으로 서버 재시작.
5. 휴대폰에 Tailscale을 설치해 PC와 같은 tailnet으로 연결한 뒤, **서버 연결** 창의 `:8443` 주소로 접속합니다.

```text
기존: https://기기명.네트워크.ts.net        → 기존 Funnel 443 유지
추가: https://기기명.네트워크.ts.net:8443   → Tailscale Serve 개인 경로
```

8443 경로는 **휴대폰 Tailscale 연결이 필요**합니다. 두 주소는 같은 라이브러리를 사용하지만
서로 다른 origin이므로 처음에는 각 주소에서 따로 로그인합니다. 세션 쿠키도 별도 이름으로 두어 충돌을 방지했습니다.

직접 연결이 가능할 때 개선 여지가 크지만 NAT/회선 때문에 relay 연결일 수 있습니다.
**이 도우미는 속도를 보장하지 않고, 방화벽/공유기/PC 절전을 임의로 바꾸지 않습니다.**

서버 PC에서 다음으로 현재 상태를 확인할 수 있습니다.

```bat
tailscale serve status
tailscale funnel status
tailscale status
```

휴대폰으로 통신한 뒤 `tailscale status`의 `direct` / `relay` / `peer-relay`를 확인하세요.
다른 서비스가 8443을 이미 사용하면 경고를 읽고 중단할 수 있습니다.
해제는 **`OPTIONAL_remove_private_fast.bat`**이며 443을 초기화하지 않습니다.

## 로그인 / 보안 유지

비밀번호 8자 이상, scrypt 저장, 30일 자동 로그인, 로그아웃/전체 기기 로그아웃,
변경 요청의 Origin/CSRF 검사, 모든 미디어의 인증을 유지합니다.
공개 Funnel에서는 로그인 시도가 외부에 열려 있으므로 추측하기 어려운 고유 비밀번호를 사용하세요.

인증 후 목록/텍스트/썸네일 응답에 ETag 재검증을 적용했습니다.
로그아웃한 뒤에는 ETag가 있어도 304로 우회하지 못합니다. 공유 캐시/public caching을 적용하지 않았습니다.
대용량 원본·재생본의 HTTP Range/HEAD 지원은 유지하며, 미디어 응답은 계속 private/no-store입니다.

SSE는 최대 8개 연결, 연결별 최신 스냅샷 하나만 유지합니다. 느린 클라이언트가 과거 진행률을 무한히 쌓지 않습니다.
15초 heartbeat는 로그인 비활성 시간을 연장하지 않습니다. 로그아웃·만료 시 연결은 종료됩니다.
이미 클라이언트에 전달된 파일은 로그아웃으로 회수할 수 없습니다.

## 처음 설치하는 경우 / 기존 도구

처음에는 `01_setup_beta.bat`에서 계정과 경로 설정 후 `run_v8_beta.bat`으로 PC에서 실행합니다.
PC 주소는 기본 `http://127.0.0.1:8765`입니다. Python 3.10 이상 및 필요한 엔진을 설치합니다.
기존 Tailscale/Funnel이 없다면 02번은 개인 Serve 443 설치 도우미입니다. 공개 Funnel을 자동 생성하지 않습니다.

| 파일 | 역할 |
|---|---|
| `run_v8_beta.bat` | 설치 환경 확인 후 서버 시작, 브라우저 열기 |
| `stop_v8_beta.bat` | 서버 정상 종료 |
| `01_setup_beta.bat` | 계정/경로 변경, 초기 설치 |
| `02_connect_tailscale.bat` | 최초 Serve 443 설정. 이미 Funnel이 있으면 보호를 위해 중단 |
| `05_connect_private_fast.bat` | 443 유지 + 개인 Serve 8443 추가 |
| `03_install_autostart.bat` | Windows 부팅 자동 시작 등록 |
| `start_background.bat` / `remove_autostart.bat` | 등록 작업 시작 / 등록 해제 |
| `04_status.bat` | 서버 상태와 연결 주소 확인 |
| `update_engines.bat` | 서버 종료 후 패키지/엔진 갱신 |

자동 시작은 여전히 **Windows 계정 비밀번호**를 작업 스케줄러에 전달하는 방식입니다.
라이브러리 비밀번호나 Windows Hello PIN과 다릅니다. PC/Tailscale/서버가 켜져 있어야 외부 접속됩니다.
선택형 Cloudflare 관리 주소는 유지되지만 영상·음원·5MB 초과 전송은 차단합니다. 이 5MB는 앱의 자체 기준입니다.

## 파일 보관 / 되돌리기

- 원본: 설정한 output 또는 가져온 원래 폴더. 삭제/이동하지 마세요.
- 계정/연결: `config/`. 외부에 업로드하지 마세요.
- 태그/목록/작업: 설정한 data의 `library.sqlite3`.
- 모바일 재생본: 같은 data의 `mobile_previews/`.
- 작은 썸네일: 같은 data의 `cache/thumbnails/`.

업데이트는 derivatives 테이블/목록 인덱스를 추가합니다. 기존 자료/태그를 삭제하는 마이그레이션은 없습니다.
되돌릴 때는 서버 종료 후 백업한 버전의 코드와 config/DB를 함께 복원하세요. 새 `fast_url` 키는 예전 프로그램이 모를 수 있습니다.
백업 이후 새로 붙인 태그/작업 기록은 백업 복원 시 없어질 수 있습니다. 원본은 복원 과정에서 지우지 마세요.
