# 검증 기록

## Pinterest 로그인 보완 — 2026-10-02

- 자동화 Chrome 로그인 화면에서 reCAPTCHA 연결 오류와 로딩 정지가 발생했습니다. 해당 로그인 작업을 중단했습니다.
- 사용자가 Pin Archive 전용 프로필을 일반 Chrome에서 열어 직접 로그인했고, 창을 닫은 뒤 Pinterest 도메인의 세션 쿠키가 프로필에 남은 것을 확인했습니다. 쿠키 값은 출력하거나 배포하지 않았습니다.
- Windows에서 Chrome/Edge를 선택한 경우 로그인 버튼이 일반 브라우저 실행 파일에 전용 프로필 경로를 전달하도록 수정했습니다. 실제 브라우저 실행은 사용자 수동 로그인으로 확인했으며, 새 버튼 코드 경로는 모의 프로세스 실행 테스트로 확인했습니다.
- 전체 오프라인 회귀 검사 92개가 통과했습니다. 실제 로그인된 수집과 계정의 보드 이미지 반영은 아직 검증하지 않았습니다.

## 1.0.1 Windows 안정화 — 2026-10-02

- 원본 ZIP은 별도 작업 폴더에 풀었으며 기존 `data/`를 이관하거나 삭제하지 않았습니다.
- Python 3.13 Windows 가상환경에서 `01_setup.bat`과 `06_test.bat`을 실제 실행했습니다. 기존 85개에 포트·상태 파일 테스트 3개를 더한 88개가 모두 통과했습니다.
- 8765·8766이 다른 프로세스에 점유된 상태에서 `02_start.bat --no-browser`가 8767을 선택했습니다. `data/runtime.json`의 포트·식별값은 `/api/health`와 일치했습니다. 종료 후 상태 파일이 제거됐고 `--port 9000`으로 재시작했습니다. 손상된 상태 파일을 넣은 뒤에도 9100에서 재시작해 새 상태 파일로 교체되는 것을 확인했습니다.
- MCP는 8767과 9000을 자동 발견했습니다. 명시적 `--base-url`도 확인했고, 실제 서버 검색 결과 3건 중 하나에 `get_image`를 호출하여 WebP 667×1000 픽셀을 디코딩했습니다.
- 크롤러 가져오기 예제는 자동 발견으로 새 PNG 1개를 등록했고, 명시적 `--server` 재실행에서는 중복 1개로 병합했습니다. 테스트 이미지는 점검 후 제거해 샘플 24개만 남겼습니다.
- `05_mcp_config.bat`을 실제 실행했습니다. 출력된 Python·브리지 경로의 존재를 UTF-8 JSON으로 확인했고, 설정에 고정 `PINARCHIVE_URL`이 포함되지 않음을 확인했습니다.
- 실제 Microsoft Edge에서 localhost 페이지를 데스크톱 1440×1000 및 모바일 390×844로 열었습니다. 두 크기에서 갤러리 25개(점검 이미지 포함), 1.0.1 표기, MCP 설정, 가로 넘침 없음, 한글 검색 1건과 상세 화면을 확인했습니다. 점검 이미지는 이후 제거했습니다.
- 실제 Pinterest 로그인·수집, OpenAI/Ollama 모델 호출, CLIP 모델 다운로드·추론, 기존 외부 크롤러 프로젝트 연결, 대규모 이미지 성능은 이번에 검증하지 않았습니다.

## 아래는 기존 1.0.0 릴리스 기록

검증일: 2026-10-02. 대상: Pin Archive 1.0.0 배포 소스.

## 환경

Python 3.13.5 / Linux, FastAPI 0.128.2, Uvicorn 0.48.0, HTTPX 0.28.1, Pillow 12.3.0, Pydantic 2.13.4, NumPy 2.3.5, python-multipart 0.0.29, Playwright 1.57.0 및 환경의 시스템 Chromium을 사용했습니다. Windows 실행 BAT는 코드 검토만 했고 실제 Windows에서 실행하지 않았습니다.

## 1. 오프라인 회귀 검사: 85개 통과

명령: `python -m unittest discover -s tests -p "test_*.py" -v`.

- 저장소: 실제 이미지 디코딩/썸네일, 바이트·픽셀 중복, 투명도와 애니메이션의 잘못된 병합 방지, 키워드/출처 병합, 보드, 삭제, 샘플 최초 등록, 한글 부분 검색, FTS 입력 처리.
- HTTP API: 실제 파일 업로드·미디어 반환·ZIP 내보내기, 출처 메타데이터, 토큰/Origin/호스트 검증, 권한 확인, 파일/요청 제한, 없는 파일·빈 결과, 비밀 키 비저장.
- 네트워크: 모의 DNS/HTTP로 사설망·혼합 DNS·리디렉션·포트·스킴 차단 확인. 실제 외부 이미지 서버 연결의 검증은 아닙니다.
- AI: 모의 OpenAI Responses/Ollama 응답으로 입력 이미지·JSON 스키마·오류 처리·수동 데이터 보존·재정렬 ID 검증. 실제 모델의 추론 품질을 평가한 것은 아닙니다.
- 의미 검색: 모의 인코더와 실제 SQLite 벡터로 cosine 정렬/RRF 및 미설치·미색인 경고 확인. CLIP 가중치를 내려받아 추론하지 않았습니다.
- MCP: 프로토콜 초기화·도구 스키마·읽기 전용·입력 검증·실제 바이트 형식·오류 반환.
- 작업: 저장 성공/부분 실패/전체 실패 구분, 대기 작업 취소, 재시작 시 중단 상태 복구, 키 로그 마스킹.

## 2. UI 점검: 23개 통과

1440×1000 데스크톱과 390×844 모바일 크기에서 확인했습니다. 실제 로컬 서버와 DB를 연결해 다음을 조작했습니다.

24개 샘플 로딩과 이미지 디코딩, 가로 넘침 여부, 카테고리 필터, 보드 생성, 파일 업로드와 신규 건수, 한글 검색, 제목/태그/설명 편집, 즐겨찾기 영구 저장, 보드 소속, 실제 이미지와 JSON 내보내기, 빈 검색 결과, 의미 검색 오류 및 하이브리드 전환 경고, 설정 저장, 안내 화면, 비어 있는 작업 기록, 허가 확인 전 수집 방지, 모바일 상세 화면과 수집 버튼 위치를 확인했습니다.

모바일에서 헤더의 backdrop-filter 때문에 고정 수집 버튼이 화면 위쪽으로 벗어나는 문제를 발견하고 수정했습니다. 최종 화면은 모바일 고정 버튼과 가로 폭을 다시 확인했습니다. 테스트 과정의 의도적 의미 검색 실패에서 HTTP 409 로그가 발생했고, 앱의 처리되지 않은 JavaScript 예외는 0개였습니다.

### UI 검증 방식의 제한

이 환경의 Chromium 관리자 정책이 localhost 직접 페이지 탐색을 차단해 `ERR_BLOCKED_BY_ADMINISTRATOR`를 반환했습니다. 정책을 변경하지 않고, 로컬 HTML을 `set_content`로 렌더하고 페이지의 HTTP 요청을 실제 로컬 서버로 중계하는 하네스를 사용했습니다. URL history 호출은 하네스에서 비활성화했습니다.

따라서 UI 조작과 실제 서버 데이터의 일치는 확인했지만, 실제 URL 탐색·브라우저 주소 저장·브라우저 자체의 Origin/CSP 강제 적용·자동 브라우저 열기까지 통과했다고 해석하면 안 됩니다. 서버 측 보안 검증은 별도의 API 검사에 포함되어 있습니다. 원래 정책으로 차단된 경로에서 직접 E2E를 통과했다고 주장하지 않습니다.

## 3. 통합 점검: 13개 통과

- 실제 별도 프로세스의 stdin/stdout으로 MCP 초기화와 5개 도구 목록을 확인했습니다.
- 실제 서버에서 자연 키워드로 이미지를 검색하고, 반환 ID로 `get_image`를 호출했습니다.
- 반환된 base64를 실제 WebP로 디코딩했고, HTTP 썸네일과 바이트가 같음을 확인했습니다.
- 없는 이미지의 오류 반환과 깨끗한 프로세스 종료를 확인했습니다.
- 기존 크롤러용 CLI로 실제 PNG와 manifest를 업로드하고 재실행 시 중복 병합, 출처/키워드 보존, 폴더 밖 경로 거부를 확인했습니다.
- 합성 DOM에서 Pin 링크·제목과 실제 제공된 srcset 중 고해상도 URL 선택을 확인했습니다. 이것은 실제 Pinterest 화면을 검증한 것이 아닙니다.

## 실제 확인하지 않은 항목

실제 Pinterest 계정 로그인과 게시 이미지 수집, 외부 URL의 다운로드 성공률, CAPTCHA/계정 제한의 모든 화면 형태, 실제 OpenAI·Ollama 비전 추론, CLIP 모델 다운로드·추론 품질·시간·메모리 사용량, 실제 AI 클라이언트의 연결 UI, ChatGPT 웹/터널 연결, Windows BAT 설치·브라우저 자동 실행, 대규모 데이터 성능, 전체 보안 감사는 검증하지 않았습니다.

`tests/`의 85개 검사는 배포본에 포함됩니다. 브라우저 QA 하네스와 일회성 테스트 DB·업로드 파일은 일반 배포본에 포함하지 않습니다. `ui_checks.json`, `integration_checks.json`, `core_tests.txt`는 결과 증거이며 UI 하네스의 재현 스크립트가 아닙니다.
