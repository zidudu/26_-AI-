# 클라우드 브라우저 시작·연결 검증

기존 control-browser를 보조하는 실행 체크리스트로 사용한다. 이 스킬 자체는 브라우저나 권한을 제공하지 않는다. 현재 브라우저 지침을 기준으로 실행하며 과거 세션의 경로·연결 객체·성공 결과를 현재 증거로 재사용하지 않는다.

## 원칙

- 시작·접속 요청에는 설명만 하지 말고 허용된 연결 절차를 실제 수행한다. 설명만 요청받으면 실행하지 않는다.
- 처음 도구 목록에 브라우저 도구가 안 보인다는 이유로 사용 불가라고 단정하지 않는다.
- 일반 정보 검색은 검색 우선, 플러그인 소관 작업은 해당 플러그인 경로를 따른다. 플러그인 실패·검색 실패의 대체 경로나 권한 우회에 이 스킬을 쓰지 않는다.
- 짧게 연결 진행을 알린다. 전문 설명을 요청받지 않으면 내부 실행 도구명보다 현재 상태를 전달한다.

## 1. 현재 브라우저 지침 읽기

현재 목록에서 control-browser를 찾아 지정된 방식으로 SKILL.md 전체를 읽는다. 목록에 없다면 제공된 스킬 목록·검색 기능으로 확인한다. 끝내 찾지 못하면 필수 브라우저 지침이 제공되지 않았다고 보고하고 중단한다.

현재 문서의 import 예시와 반환된 skill_root를 사용한다. 이전 세션의 e0/browser 별칭이나 /root/.codex/skills/browser 경로를 모든 환경에 고정하지 않는다. 현재 문서가 지정한 모듈 경로를 셸로 존재 검사하지 않는다.

## 2. 실행 도구 발견하기

현재 문서가 지정한 JavaScript 실행 도구를 찾는다. ALL_TOOLS가 제공된 code mode 환경에서는 이름·설명을 좁게 필터링한다. 전체 등록 정보를 출력하지 않는다.

```javascript
const matches = ALL_TOOLS.filter(x =>
  x.name.includes("node_repl") && x.name.endsWith("__js")
);
text(matches);
```

도구 검색 기능이 제공되면 현재 브라우저 문서의 검색 절차를 따른다. 현재 절차는 node_repl js를 결과 수 제한 없이 검색하고, 없으면 limit: 10으로 한 번 더 검색하는 것이다.

발견된 도구의 실제 이름·입력 스키마로 호출한다. js_reset이나 모듈 경로 추가 도구를 실행 도구 대신 호출하지 않는다. 제공된 발견 절차를 마쳐도 실행 도구가 없으면 중단한다. 이 경우 연결·사이트 이동은 시도되지 않았다고 명시한다.

## 3. 초기화와 브라우저 선택

이미 같은 실행 세션에서 연결하고 문서를 읽은 유효한 browser 객체가 있으면 재사용한다. 새 사용자 메시지나 빈 탭 목록만으로 초기화·재선택하지 않는다. 변수 중복 선언을 피한다.

새 실행 세션에서는 현재 control-browser의 정확한 절대 경로와 초기화 코드를 사용한다. 아래는 구조 예시이며 경로는 현재 지침으로 채운다.

```javascript
const { setupBrowserRuntime } = await import(
  "<현재 스킬 루트>/scripts/browser-client.mjs"
);
const agent = await setupBrowserRuntime({ environment: "cloud" });
const browser = await agent.browsers.get("cdp");
nodeRepl.write(await browser.documentation());
```

반드시 발견한 Node REPL js 도구에서 실행한다. 셸 Node, 독립 Playwright, 직접 CDP 연결로 대체하지 않는다. code mode에서 최초 documentation 호출을 감싸면 현재 지침에 따라 바깥 exec 첫 줄에 다음 pragma를 넣고 문서 결과를 전부 전달한다.

```javascript
// @exec: {"max_output_tokens": 20000}
```

브라우저 문서를 전체 읽은 뒤 조작한다. 문서를 미리 자르거나 요약하지 않는다. import 실패 시 다른 추측 경로나 패키지명으로 시도하지 않는다. 초기화 성공 후 브라우저 발견·선택 실패라면 현재 지침의 bootstrap-troubleshooting 문서를 읽고 허용된 진단만 한다. 권한·승인 제한은 중단 조건이다.

## 4. 요청 범위 실행과 검증

- 시작만 요청받으면 브라우저 선택 결과와 탭 목록 등으로 연결을 확인한다. 임의 사이트를 시험 대상으로 열지 않는다.
- 사이트 열기 요청이면 문서화된 API로 탭을 얻거나 생성해 해당 주소로 이동한다. 같은 주소면 불필요하게 새로고침하지 않는다. 기존 탭의 입력 중인 작업을 덮어쓰지 않는다.
- 새 탭 생성 여부를 보고하려면 실행 분기에서 실제 확인한다.
- 현재 문서에 API가 있는 것을 확인한 뒤 tab.url(), tab.title(), tab.playwright.domSnapshot()으로 최종 URL·제목·페이지 상태를 확인한다. 빈 화면·차단 원인이 불명확하면 브라우저 지침에 따라 스크린샷도 확인한다.
- DOMContentLoaded는 모든 이미지·영상 로딩 완료를 뜻하지 않는다. URL·제목만 확인했다면 그 범위만 보고한다.
- 로그인은 현재 browserAuth 지침을 따른다. 비밀번호·OTP를 채팅으로 받거나 일반 입력 API로 넣지 않는다. CAPTCHA·차단·사용자 인계는 현재 브라우저 문서의 확인·중단 규칙을 따른다.
- 네트워크 오류와 사이트 봇 차단을 구분한다. 차단 우회나 무한 재시도를 하지 않는다.

## 5. 증거에 맞춰 보고하기

성공하면 연결 완료 또는 사이트 접속 완료와 실제 확인한 상태를 짧게 보고한다. 링크가 필요하면 탭에서 확인한 안전한 최종 URL을 그대로 사용한다.

실패하면 아래 단계와 직접 관찰한 결과를 밝힌다.

| 단계 | 보고할 관찰 사실 |
| --- | --- |
| 스킬 발견·읽기 | 필수 지침 미제공 또는 읽기 실패 |
| 실행 도구 발견 | 지정된 검색 후에도 실행 도구 미발견 |
| 모듈 불러오기 | 문서에 지정된 모듈 import 실패 |
| 초기화·브라우저 선택 | 해당 호출에서 반환된 오류 |
| 페이지 이동 | 연결 성공 후 요청 사이트 이동 실패 |
| 사이트 상태 | 로그인 요구, 빈 페이지, 검증 요청 등 |

비밀값과 세션 식별자는 출력하지 않는다. 원인을 특정 모델·추론 수준·요금제·세션 차이 탓으로 단정하지 않는다. 다른 세션의 실패 원인을 확인하려면 그 세션의 실행 기록이 필요하다.

완료 전 확인한다: 실제 호출을 했는가? 성공 주장을 뒷받침할 결과가 있는가? 미시도 단계와 실패 단계를 구분했는가? 현재 권한과 요청 범위를 지켰는가?
