# SUNO v6 음악 제작

기준: 2026년 9월. 기능 근거와 미검증 사항은 REFERENCES.md를 참고한다.
사용자가 정한 방향을 우선하며 아래 순서는 필요에 따라 생략·변경한다.

## 1. 목적에 맞게 설계한다

목적, 분위기, 보컬 유무, 핵심 악기, 반복성, 참조 자료를 파악한다.
이미 받은 정보는 다시 묻지 않는다. 부족한 내용은 합리적으로 가정하고,
결과를 크게 바꾸는 불확실성만 질문한다.

참조 작품의 특징을 리듬, 음색, 멜로디, 화성, 악기 역할, 편곡으로 풀어낸다.
제목이나 아티스트 이름만으로 원하는 음악을 설명하지 않는다.
이전 제목과 상투적인 단어를 반복하지 않고 곡에 맞는 제목을 정한다.

새로운 기능·지원 조건이 중요하면 최신 Suno 공식 자료와 현재 UI를 확인한다.
v5/v5.5 정보를 v6에 자동 적용하지 않는다. 문서 충돌과 미확인 부분을 남긴다.

## 2. 입력과 길이 제한을 지킨다

- Style: 최대 1,000자. 별도 요청이 없으면 영어로 작성한다.
- Lyrics: 최대 5,000자. 사용자가 요청한 가사 언어를 따른다.
- 공백, 줄바꿈, 문장부호, [] 지시를 포함한 실제 입력 전체를 센다.
  코드 블록 표시와 입력 밖 설명은 제외한다.
- 출력 전에 도구로 길이를 확인하고 초과하면 줄여서 다시 측정한다.
  도구가 없으면 상한보다 충분히 짧게 작성하고 정확한 측정값을 꾸며내지 않는다.
- 제한은 상한이며 채워야 하는 목표 분량이 아니다.

Style에는 장르, 분위기, 리듬, 핵심 악기, 모티프, 편곡, 보컬,
프로덕션 중 필요한 특징만 우선순위대로 담는다.
독특함은 악기 수를 늘리기보다 리듬·음색·화성 등의 특징으로 만든다.

보컬곡은 의미, 음절, 프레이즈 길이, 발음, 강세와 반복을 함께 고려한다.
사용자가 제시한 음절 틀을 우선한다. [Verse], [Chorus], [Bridge] 등의
구조 태그를 활용하되 자유형 [] 지시는 확정 명령어로 취급하지 않는다.

무보컬곡은 Instrumental 기능을 우선한다. Lyrics 메타 지시는 필요할 때만
추가한다. 요청받지 않은 실제 가사를 무보컬곡에 넣지 않는다.

게임 BGM은 짧고 기억되는 모티프, 반복성, 낮은 청취 피로,
역할이 분명한 소수 악기와 안정적인 편곡을 우선한다.
장면에 불필요한 악기 증가와 클라이맥스를 줄인다.
일반 완곡의 완벽한 루프를 보장하지 않는다. 짧은 루프는 Sounds의 Loop를
검토하고 실제 연결부를 확인한다. 필요하면 자르기·크로스페이드를 고려한다.

## 3. 모델·입력·설정을 선택한다

Simple은 빠른 구상과 복합 자연어 요청, Advanced는 입력과 옵션의
직접 구성, Sounds는 One Shot·Loop 샘플 제작에 활용한다.
v6는 구체적인 의도 구현, v6-wild는 실험적 탐색,
v6-mini는 빠른 반복의 후보로 삼는다. 이용 가능한 모델을 확인한다.

오디오는 허밍·연주·리듬 등의 출발 소재로 사용한다.
Voice는 보컬 성별과 구분하고 현재 모델 호환성을 확인한다.
Inspo의 기존 공식 설명은 자신의 곡 플레이리스트 참조이며,
v6의 텍스트·오디오·이미지·영상 다중 입력 능력과 구분한다.

| 옵션 | 판단 기준 |
|---|---|
| Exclude | 피할 악기·장르·요소를 간결하게 지정한다. |
| Vocal Gender | 보컬곡에 필요한 성별 방향을 지정한다. |
| Length | 현재 UI의 범위와 단위를 확인하고 목표 길이를 정한다. |
| Weirdness | 예측 가능성과 실험성을 조정하는 후보로 다룬다. |
| Style Influence | Style을 따르는 강도를 조정한다. |
| Audio Influence | 표시되는 경우 참조 오디오 반영 정도를 시험한다. |
| Variety | Style 문구 변형 기능. 원문 통제가 중요하면 공식 안내의 0을 출발점으로 삼고 실제 UI 형식을 확인한다. |
| Max Mode | 2분 초과 곡, 원곡에 가까운 Cover, 스타일 이전, 보컬·스타일 일관성에 검토한다. 추가 크레딧을 고려한다. |
| My Taste | 취향 기반 개인화. 기존 Magic Wand 설명만으로 현재 토글의 적용 범위를 단정하지 않는다. |

설정 요청에는 실제 입력할 수치 또는 ON/OFF와 짧은 이유를 제시한다.
공식 수치와 실험용 시작값을 구분하며 장르별 만능 프리셋을 만들지 않는다.
화면에 없는 옵션, 확인하지 않은 범위·기본값을 임의로 적용하지 않는다.
여러 옵션을 동시에 바꾸기보다 현재 문제와 관련된 것부터 조정한다.

## 4. 기존 곡을 수정·재활용한다

먼저 원본에서 유지할 요소와 변경할 요소를 정한다.
Remix/Edit는 여러 작업을 묶는 범주로 이해하고 목적에 맞는 기능을 고른다.

| 목적 | 기능과 적용 기준 |
|---|---|
| 원곡을 다른 장르·편곡·보컬로 재해석 | Cover. 보존할 멜로디·구조와 변경할 특징을 명시한다. |
| 같은 입력으로 새 결과 생성 | Reuse Prompt / Use Styles and Lyrics. 입력 재사용이며 멜로디 보존을 보장하지 않는다. |
| 곡 연장·뒷부분·엔딩 변경 | Extend. 유지할 지점과 이어 만들기 시작할 시점을 정한다. |
| 특정 구간의 가사·음악 수정 | Replace Section / 부분 편집. 대상 구간과 앞뒤 연결을 확인한다. |
| 곡의 소리·균형을 다듬기 | Remaster. 큰 가사·장르 변경 용도로 선택하지 않는다. |
| 앞뒤 자르기·속도 조정 | Crop / Adjust Speed. 필요한 범위만 편집한다. |
| 반주에 보컬 추가 | Add Vocals. 지원되는 입력인지 확인하고 가사와 보컬 방향을 작성한다. |
| 여러 곡의 요소 결합 | Mashup. 소스별로 가져올 보컬·드럼·리프 등의 역할을 명시한다. |

Remaster의 Variation strength는 Subtle(작은 보정), Normal(가벼운 변화),
High(더 큰 변형) 중 목적에 맞게 선택한다. High는 음악 요소나 보컬도
달라질 수 있으므로 결과를 확인한다.

기존 곡 작업에는 원본 소스, 유지·변경 조건, 필요한 구간 또는 시작 시점,
복사할 입력과 해당 기능의 설정을 제공한다.
v6의 자연어 편집을 활용할 수 있지만 실제 메뉴·지원 범위는 확인한다.
생성형 편집의 원본 보존을 보장하지 않는다.
다른 사람의 곡을 사용할 때는 해당 곡의 리믹스 허용 상태를 확인한다.
공개·수익화가 요청되면 원본 출처와 현재 이용 조건을 별도로 확인한다.

## 5. 결과를 관찰하고 필요한 부분만 고친다

문제를 스타일, 멜로디, 악기, 편곡, 반복, 보컬, 가사, 믹스,
참조 반영 중 어디에 해당하는지 좁힌다.
악기가 많으면 편성과 Exclude, 스타일 이탈이면 입력 충돌과
Variety·Style Influence를 먼저 점검한다.
좋은 곡의 일부만 문제라면 부분 편집, 음질·균형만 문제라면 Remaster를 검토한다.

비교할 때 원본 입력과 설정을 기록하고 핵심 변수 하나부터 바꾼다.
생성의 무작위성을 고려하며 한 쌍의 결과만으로 원인을 확정하지 않는다.

실제 조작 도구가 있으면 사용자가 요청한 범위에서 입력·생성·확인을 수행한다.
도구가 없으면 복사할 입력을 제공한다. 입력 준비, 생성 요청, 생성 완료,
실제 청취를 구분하고 수행하지 않은 작업을 완료했다고 말하지 않는다.

기본 출력은 제목, Style, Lyrics 또는 Instrumental 안내, Exclude,
필요한 설정값이다. 각 입력은 별도 코드 블록으로 제공하고
여러 곡이면 제목·입력·설정의 대응을 명확히 한다.
특정 항목만 요청하면 해당 항목만 출력한다.

정보는 필요할 때 Official(해당 범위의 공식 확인),
Validated(실제 반복 검증), Experimental(시작값·가설·미검증)로 구분한다.
이 스킬을 만들기 위한 직접 생성·청취 실험은 아직 수행하지 않았다.
