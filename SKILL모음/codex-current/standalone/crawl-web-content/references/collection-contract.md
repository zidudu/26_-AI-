# 수집 상태·중복·출력·재개

여러 글을 수집하거나 크롤러를 구현할 때 사용하라. 사용자가 지정한 스키마가 있으면 그 형식을 우선하고, 아래 필드의 의미만 보존하라. 단일 글에는 필요한 부분만 적용하라.

## 요청 범위와 실행 범위를 구분하라

실행 설정에 시작 URL·허용된 대상 도메인/작성자·키워드·날짜와 시간대·필드·종료 조건을 기록하라. 사용자가 수량이나 날짜를 지정했다면 원래 값을 유지하라. 작은 표본 검증 후 전체 실행은 이미 받은 수집 지시에 따라 계속하되, 접근 차단이나 불확실한 상태는 명시하라.

API·RSS·검색 결과는 각기 발견 가능한 범위가 다르다. 검색 인덱스의 결과 수를 블로그의 전체 게시물 수로 해석하지 마라. 피드의 최근 항목만 읽고 과거 글까지 완료했다고 말하지 마라.

## 글과 발견 경로를 분리하라

| 필드 | 의미 |
| --- | --- |
| `post_key` | 사이트와 확인된 글 ID를 조합한 문자열. 글 ID가 없으면 실제로 확인한 정규 URL 사용 |
| `source_url` | 실제 발견한 원본 URL. 정규화된 키와 별도로 보존 |
| `discovered_from` | 원본 행·키워드·목록 URL 등 발견 경로의 배열 |
| `title`, `author` | 확인된 제목·작성자. 확인되지 않으면 빈 값 |
| `published_at_raw` | 화면/API에 표시된 원래 작성일 |
| `published_at` | 확실히 해석한 날짜·시간. 불명확하면 null |
| `content` | 확보한 본문·발췌·요약 텍스트 |
| `content_kind` | `full_text`, `excerpt`, `summary`, `none` 중 실제 확보 수준 |
| `status` | 아래 수집 상태 |
| `collected_at` | 실제 수집 시각과 시간대 |
| `error_stage`, `error_detail` | 실패 단계와 필요한 최소 근거 |

`full_text`는 요청한 텍스트 본문 범위를 확인했다는 뜻이다. 이미지의 글자·첨부파일까지 확보했다는 뜻은 아니다. API 검색 요약은 `excerpt`, AI가 재작성한 요약은 `summary`로 구분하라. 요청이 전체 본문인데 발췌만 있으면 그 건을 `partial`로 기록하라. 발췌가 요청 범위라면 발췌 수집 자체를 성공으로 처리할 수 있다.

글 번호·시리얼 등 식별자는 문자열로 유지하라. 쿼리·프래그먼트가 다른 콘텐츠를 가리킬 수 있으므로 일괄 제거하지 마라. 제목만 같다는 이유로 중복 글을 합치지 마라. 네이버 `blogId + logNo`처럼 현재 근거가 확인된 경우에만 플랫폼별 정규화 규칙을 적용하라.

본문 조회를 공유해도 모든 `discovered_from` 항목을 남겨라. 동일 URL을 서로 다른 키워드로 발견했다면 글 1개·발견 2건이다. 실패한 글을 완료 키 집합에 넣어 재개 시 건너뛰지 마라.

## 결과와 실패를 분류하라

| `status` | 사용할 조건 |
| --- | --- |
| `success` | 요청한 필드·내용 범위를 확인하고 결과에 기록함 |
| `partial` | 일부 내용만 확보했거나 전체 본문 여부가 불명확함 |
| `access_denied` | 로그인·열람 제한 등 실제 접근 제한을 확인함 |
| `not_found` | 해당 글의 삭제·존재하지 않음을 명시한 상태를 확인함 |
| `timeout` | 제한 시간까지 기대 조건을 확인하지 못함 |
| `extraction_failed` | 글은 열렸지만 본문이나 필드를 식별하지 못함 |
| `pending` | 아직 처리하지 않았거나 중단으로 남음 |

임시 빈 DOM, HTTP 200, 검색 결과 없음, 짧은 본문만으로 다른 상태를 단정하지 마라. 검색 결과 0건은 해당 검색의 결과이지 각 글이 삭제됐다는 증거가 아니다. 사이트가 봇 차단이라고 명시하지 않은 제어 도구 오류를 봇 차단으로 보고하지 마라.

## 확장과 종료를 검증하라

- 클릭 전에 현재 필터·페이지·글 키 집합을 기록하고, 동작 후 조건이 충족된 새 결과만 다음 배치로 처리하라.
- 고정 수면만으로 연결하지 말고 관찰한 준비 조건에 시간 제한을 두라. 로딩 중 요소의 일시 소실과 명시된 마지막 페이지를 구분하라.
- 새 글이 나오지 않으면 실제 끝 표시·현재 필터·오류 상태를 확인하라. 안전한 읽기 재시도는 횟수를 제한하고 사이트의 제한을 존중하라. 근거 없는 반복 요청이나 차단 우회로 확장하지 마라.
- 전체 실행 완료는 요청 수량/범위를 충족하거나 명확한 목록 끝을 확인하고 남은 글 상태를 정리한 때에만 선언하라. 근거 없는 반복 정체는 `incomplete`이며 완료가 아니다.
- 필터가 바뀌면 이전 결과·늦은 응답을 새 필터의 결과로 섞지 마라. 식별 불가능하면 해당 단계에서 중단하고 확인 필요 상태를 남겨라.

## 재개와 출력

페이지 DOM 밖의 실행 기록에 설정/입력 목록 식별자, 발견 경로, 완료 글 키, 실패/미처리 키, 마지막으로 확인한 목록 위치를 보존하라. 결과가 실제로 기록된 글만 완료로 표시하라. 저장은 원자적 파일 교체나 트랜잭션 등 구현 환경에 맞는 방식으로 처리하라. CSV라면 기존 결과로 완료 키를 복구하는 등 결과 파일과 체크포인트 사이의 불일치를 고려하라.

설정·대상 목록이 달라졌다면 이전 커서를 맹목적으로 이어 쓰지 마라. 재연결은 화면 문맥 복구이며 이미 완료한 글을 재저장하는 지시가 아니다. 실패 건의 재시도는 원래 실패 상태와 횟수를 남겨라.

기본 출력은 글별 결과와 실행 요약이다. CSV에는 줄바꿈·따옴표를 올바르게 이스케이프하고, 웹에서 온 값을 스프레드시트 수식으로 실행하지 않도록 내보내라. 다대다 발견 경로는 JSONL 배열이나 별도 발견 목록으로 보존하라. 출처가 필요한 값과 AI가 만든 분류/요약은 열을 구분하라.

실행 요약에는 발견 건수, 고유 글 수, 중복 발견 건수, 상태별 건수, 요청 범위 충족 여부, 완료/중단 근거를 남겨라. 발견=고유+중복은 동일한 집계 범위에서만 사용하고, 범위 밖 제외 건·아직 읽지 않은 글을 성공에 섞지 마라. 정적 검토·모의 입력 검증·실사이트 표본·전체 실행을 구분하여 보고하라.
