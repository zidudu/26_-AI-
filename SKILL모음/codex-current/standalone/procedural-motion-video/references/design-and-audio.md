# ORBIT 구현과 변형

## 소스 지도

| 파일 | 책임과 수정 위치 |
| --- | --- |
| src/Root.tsx | composition ID, 해상도, fps, 전체 프레임 수 |
| src/Composition.tsx | 음악 파일, 장면 순서와 각120프레임의 길이 |
| src/scenes/Design.tsx | 브랜드 헤더, Sphere, 궤도·위성·그림자 공통 표현 |
| src/scenes/Spark.tsx | 점→구체 확대, 첫 제목, 첫 원형 wipe |
| src/scenes/Motion.tsx | 두 줄 제목, 궤도 도입, 두 번째 wipe |
| src/scenes/Orbit.tsx | 브랜드 엔딩, 밝은 구체, 밑줄 완성 |
| make_audio.py | 12초/120BPM 합성음·화음·박자·믹싱 |

초기 템플릿은 절대 좌표 기반입니다. 세로형1080×1920에서 좌우84px, 헤더약116px, 주 메시지약300px, 중심 아트약690px, 하단 문구1518px로 시각적 위계를 만듭니다. 이 값은 플랫폼 공통 안전영역 규정이 아닙니다. 새 비율과 게시 플랫폼에 맞춰 배치를 확인합니다.

## 장면의 역할

Spark 0–119: 작은 점이 구체로 자라며 시작을 보여 줍니다. Motion 120–239: 궤도와 위성을 더해 리듬을 만듭니다. Orbit 240–359: 브랜드와 결론을 밝은 색상으로 정리합니다. 이를 제품 소개에서는 문제→작동→가치로 바꾸는 등 메시지의 인과관계에 맞춥니다.

색상은 어두운 보라 #14101e, 크림 #eae8e0, 라벤더 #bca0ee, 라임 #d6ff64를 사용합니다. 글꼴은 Malgun Gothic/Arial 계열입니다. 다른 컴퓨터에서 사용 시 실제 설치 글꼴을 확인하고 필요한 경우 가용 글꼴로 교체합니다. 폰트 파일은 번들에 포함하지 않았습니다.

## 프레임 기반 운동

`useCurrentFrame()`은 Sequence 내부에서 장면의 로컬 프레임입니다. 30fps에서120프레임은4초이며 실제 샘플은0…119입니다. 보간 끝점120 자체는 그 장면에서 렌더되지 않습니다.

Spark의 스케일은 프레임[0,10,48,108,119] → [.018,.018,1,1.04,1.14]입니다. 제목은 투명도와 수직 이동을 함께 바꾸며 `Easing.bezier(.16,1,.3,1)`을 사용합니다. 이징 및 속도는 문구의 길이·분위기에 맞춰 조정하고 필요 범위 밖 보간에는 clamp를 둡니다.

위성은 θ = .027f + .66πi, x = 540 + 405cosθ, y = 390 + 295sinθ로 움직입니다. 링은 프레임당 .75도 회전합니다. fps를 바꾸면서 운동 시간을 유지하려면 프레임 계수 대신 초 단위 시간 f/fps로 계산하도록 수정합니다.

구체는 radial-gradient·inset shadow·blur highlight로 만들고, 뒤쪽 SVG 타원 → 구체 → 앞쪽 SVG 부분 타원/위성 순서로 겹칩니다. `strokeDasharray="980 2000"`는 앞쪽 궤도처럼 보이게 하는 시각적 근사이며 자동 깊이 판정은 없습니다.

## 전환

첫째·둘째 장면의112…120 구간에 다음 배경색 원을 `clipPath: circle()`로0…170%까지 확장합니다. 중심은 각각85%70%,15%70%입니다.119프레임에서 이미 전체 화면을 덮는지 확인합니다. 다음 장면 시작 배경과 색이 맞아야 합니다.

현재 TransitionSeries는 Sequence만 연속 배치하며 TransitionSeries.Transition을 통한 겹침은 없습니다. 실제 overlap 전환을 넣을 때는 전체 프레임 수가 달라질 수 있으므로 composition과 음악 길이를 다시 계산합니다.

## 음악 합성

12초,48kHz,2채널 배열에 파형을 더합니다. NumPy 난수시드913으로 재현 가능한 하이햇/클랩을 만듭니다.120BPM은 .5초/박,4초 장면은8박입니다. 장면 경계와 음악의 구조가 일치하지만 오디오 분석에 의해 움직임이 자동 반응하는 구현은 아닙니다.

- 킥: phase = 2π(47t + 105×.026×(1−exp(−t/.026))). 순간 주파수는152Hz에서47Hz로 감소합니다. 빠른 어택과 exp(−15t) 감쇠를 곱합니다.
- 화음 MIDI: [53,60,65,68], [56,60,63,68], [51,58,63,67]. 음 주파수는440×2^((MIDI−69)/12)입니다.
- 패드: 화음 사인파 평균, 완만한 어택/릴리스. 플럭: 기본파+두 번째 배음, 빠른 감쇠. .25초 간격 및 .1875초 지연 복사본을 사용합니다.
- 베이스: 화음 근음을 한 옥타브 낮춥니다. 노이즈 차분과 감쇠로 클랩·하이햇을 만듭니다.
- 팬: 좌우 sqrt((1−pan)/2), sqrt((1+pan)/2) 이득. 합산 후 tanh(mix×1.12),20ms 페이드인,650ms 페이드아웃, 최대 샘플 진폭.88 정규화 후16-bit PCM WAV로 저장합니다.

음악 길이를 바꾸려면 DURATION만 수정하지 말고 킥의 range(23), 4초 화음 구간, 플럭 step 수, 마지막 벨11초, 페이드 샘플 수와 영상 시퀀스 길이도 함께 조정합니다. 새로운 BPM에서는 초/박=60/BPM으로 시간표를 다시 만듭니다. 무음·음성·외부 음원을 선택한 요청에는 이 합성을 강제하지 않습니다.

원본 WAV에서 확인한 샘플 피크는약−1.11dBFS, RMS는약−16.09dBFS였습니다. 새 합성 결과는 다시 측정해야 하며 LUFS나 AAC 인코딩 뒤 true peak로 간주하지 않습니다.
