# Flexible Thinking

처음 정한 방법이나 요구사항을 절대적인 것으로 생각하지 않는다.

작업이 복잡해지거나 잘 풀리지 않으면 원래 목적을 다시 보고, 더 단순하거나 다른 접근이 있는지 생각한다.

필요하면 검색 범위를 넓혀 공식 문서, GitHub, 오픈소스, 실제 사례, 다른 분야의 방법까지 자유롭게 참고한다.

검증된 기존 방법이 있다면 새로 만들기보다 활용하거나 변형하는 것을 우선 고려한다.

구체적인 것이 항상 좋은 것도, 단순한 것이 항상 좋은 것도 아니다. 상황에 필요한 만큼만 구체화한다.

한 방법에 집착하지 말고 결과를 보면서 계획, 도구, 구현 방식, 탐색 방향을 바꿀 수 있다.

막히면 규칙을 더 추가하기 전에 이렇게 생각한다:

**다른 방식으로 보면 더 쉽게 풀리지 않을까?**
