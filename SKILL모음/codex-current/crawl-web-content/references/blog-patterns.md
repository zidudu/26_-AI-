# 블로그별 관찰 근거와 재검증 항목

2026-09-09 공개 페이지에서 관찰한 사례이다. 플랫폼 전체의 보장된 구조나 실행 기본값이 아니다. 목표 사이트의 현재 DOM·실제 클릭 결과와 비교하고 맞지 않는 선택자를 그대로 실행하지 마라. 이 자료를 읽었다는 사실은 새 작업의 실사이트 검증이 아니다.

## 네이버 블로그

표본: https://blog.naver.com/blogpeople/224309230211

- 샘플의 본문은 `iframe#mainFrame` 안에 있었다. 프레임 내부 `.se-title-text`와 `.se-main-container`가 각각 유일하게 제목과 본문을 가리켰다.
- 같은 제목을 전체 텍스트로 찾으면 상단 제목과 하단 목록에서 두 개가 잡혔다. 글 영역을 먼저 좁혀라.
- `블로그 이벤트 목록열기` → 해당 글 목록 표 → `2` 페이지 링크 순으로 조작했다. 클릭 직후 옛 5개 행이 남았다가 다른 글 번호의 5개 행으로 바뀌었다. 바깥 URL은 그대로였다.
- 목록의 5개 행과 카테고리 전체 282개 표시는 다른 수량이다. 현재 카테고리·정렬·표의 의미를 확인하라.
- 글 링크의 `blogId`와 `logNo`가 글 식별 근거였다. 탐색용 쿼리가 달라도 두 값이 같으면 동일 글 후보로 처리하되 원본 URL을 보존하라. 구형 에디터·다른 스킨·모바일 DOM은 별도 확인 대상이다.

키워드로 주소를 발견할 때 공식 검색 API를 검토할 수 있다. 공식 문서상 `description`은 요약문이고 제목·URL·블로그 정보·작성일을 반환한다. 문서에서 확인한 `start` 최댓값은 1000이다. 전체 과거 글·전체 본문을 제공한다고 해석하지 마라. 현재 문서와 인증·사용 조건을 확인한 뒤 사용하라. API 실호출은 원래 표본 분석에서 수행하지 않았다.

공식 자료: https://developers.naver.com/docs/serviceapi/search/blog/blog.md

## 티스토리

표본: https://notice.tistory.com/ 및 https://notice.tistory.com/2704

- 목록 카드는 `.post-item`, 글 링크는 그 내부 `a`였다. 상세 제목은 `.hgroup h1`, 본문은 `#article-view .contents_style`에서 확인했다.
- `목록 더보기` 링크의 목적지는 `/?page=2`였지만 클릭 후 URL은 유지됐다. 로딩 후 카드가 8 → 16개로 늘고 다음 목적지가 `/?page=3`으로 바뀌었다.
- 따라서 이 클릭 경로에는 새 카드·새 글 키와 다음 링크의 변화를 완료 조건으로 사용한다. 모든 스킨이 같은 추가 로딩 방식이라고 가정하지 마라.
- `article#content` 전체에는 관련 글·댓글·댓글 입력창도 들어 있었다. 본문 범위를 좁혀라. 댓글의 이전 댓글 더보기는 본문 수집과 별개이다.
- 원래 표본은 렌더링된 DOM에서 확인했다. HTTP 응답만으로 동일하게 추출 가능한지는 실제 요청을 사용해 별도로 검증해야 한다.

사이트맵 자동 생성은 공식 안내가 있다. 현재 대상 사이트맵의 포함 범위를 확인해야 하며 원래 분석에서는 사이트맵 실물을 검사하지 않았다. 과거 Open API는 종료 공지가 있으므로 오래된 API 예제를 곧바로 실행 경로로 삼지 마라.

공식 자료:
- https://notice.tistory.com/2537 — 사이트맵 안내
- https://notice.tistory.com/2664 — Open API 순차 종료 공지

## Velog

표본: https://velog.io/@dev-dino22/posts

- 작성자 목록에서 전체 38개라는 표시가 있었지만 추가 로딩 중 렌더링된 제목은 25개, 이후 35개였다. 화면의 글 수만으로 전체 완료를 주장하지 마라.
- 스크롤 동작 한 번에서 제어 도구 시간 초과가 발생했다. 실제 화면을 다시 읽은 뒤 마지막으로 확인한 글 링크에 `End` 키를 보내 추가 로딩을 확인했다. 이 현상은 봇 차단의 근거가 아니며 `End`를 모든 사이트의 필수 순서로 고정하지 마라.
- 작성자 옆 태그 목록의 `React`는 `/@dev-dino22/posts?tag=React`, 카드에 붙은 `React`는 `/tags/React`로 이동했다. 필터 후 같은 이름의 링크가 세 개였다. 옆 `complementary` 영역과 목적지를 함께 확인하라.
- 태그 클릭 직후 기존 목록이 남았다가 필터 URL과 글 두 개로 바뀌었다. 새 필터와 새 결과의 연결을 확인하라.
- Context API 관련 샘플 상세 글에는 `h1`은 있었으나 `article` 요소는 없었다. `.atom-one`을 포함하는 `div`가 본문 하나를 가리켰고 `pre` 코드 블록 8개를 포함했다.
- `.atom-one`도 현재 샘플의 후보이다. 자동 생성된 `sc-...` 클래스, 코드 색상 테마 클래스의 장기 안정성을 보장하지 마라. 본문을 확인한 뒤 문단·제목·목록·코드 순서를 보존하라.
- 광고용 iframe을 본문 프레임으로 오인하지 마라. 이 사례의 본문은 일반 문서 영역이었다. 내부 GraphQL/API는 원래 분석에서 관찰·검증하지 않았다.

## WordPress / WordPress.com

표본: https://wordpress.com/blog/ 및 https://wordpress.com/blog/2026/09/09/grow-website-traffic/

- 대표 글은 `article.wpblog-hero`, 일반 카드는 `article.wpblog-card`였다. `.wpblog__post-grid`가 여러 영역에 있어 최신 글·추천 글을 구분해야 했다.
- `Show more` 직후 버튼이 잠시 사라지고 기존 카드가 남았다. 이후 버튼이 다시 나타나고 검사한 여러 그리드의 카드 합계가 12 → 21개로 증가했다. 로딩 후 최신 목록 18개와 다른 그리드 3개를 별도로 확인했다.
- 이 수량은 전체 블로그 글 수가 아니다. 대표 글은 별도 영역이었다. 제목 링크와 이미지 링크가 같은 글로 갈 수 있으므로 카드 수·링크 수·고유 글 수를 구분하라.
- 초기 그리드의 `wpblog-grid-filter` 클래스가 추가 로딩 후 관찰에서는 없었다. 초기 클래스만으로 다음 조작 대상을 계속 찾지 마라.
- 상세 제목은 `h1.wpblog-title__post-title`, 본문은 `#wpblog-post-body`, 샘플 글 식별자는 `article#post-86998`이었다. 다른 WordPress 테마에 그대로 적용하지 마라.

공식 REST API는 글 목록·본문, `page`, `per_page`, 날짜 필터 등을 문서화한다. 해당 사이트의 지원 여부·공개 범위·실제 응답은 별도 확인하라. WordPress.com의 공개 RSS도 새 글 발견에 검토하되 최신 항목 수와 요약/원문 여부를 확인하라. 원래 표본 분석에서 이 사이트의 API·RSS 실호출은 검증하지 않았다.

공식 자료:
- https://developer.wordpress.org/rest-api/reference/posts/
- https://wordpress.com/support/feeds/
